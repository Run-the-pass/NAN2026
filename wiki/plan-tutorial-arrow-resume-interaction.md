# 튜토리얼 화살표·이어하기·상호작용 보정 계획

## 확정된 방향

- 화살표 에셋은 제거하지 않고 대상 그림·타일의 바깥쪽으로 뺀다.
- 화살표별 위치·방향·흔들림을 사용자가 한 파일에서 직접 수정할 수 있게 한다.
- 하단 대화창은 어두운 막과 하이라이트된 우측 정보창보다 앞에 표시한다.
- 푸름이 선택 화살표는 몸에 겹치지 않고 기준 타일보다 한 타일 위에 둔다.
- 퐁당이가 소개되는 순간을 새 턴의 경계로 삼아 푸름이와 퐁당이 모두 행동력을 받고 시작한다.
- 정산창의 `모드 선택`은 `나가기`로 바꾸고, 나갔다가 아르바이트 모드를 다시 누르면 `이어하기` / `처음부터` 선택을 먼저 묻는다.
- 별 진행도와 이어할 스테이지는 서버 없이 브라우저 쿠키에 저장한다.
- 선택한 슬라임으로 설비를 누르는 것은 거리와 무관하게 상호작용 시도다. 멀면 선택을 풀지 말고 `옆 칸에 서야 합니다`를 보여 준다.

## 1. 화살표 배치를 한 곳에서 조정

`app/tutorial-arrow-layout.ts`를 화살표 배치값만 담는 작은 설정 파일로 추가한다. 다른 추상화나 의존성은 추가하지 않는다.

- `dialogue`: `orders`, `next-order`, `earth`, `inspector`, `clock` 각 연출의
  `top/left/right`, `rotate`, `bobX/bobY`.
- `tutorial`: `SELECT_EARTH`, `MOVE_TO_CABBAGE`, `PICK_CABBAGE`,
  `MOVE_TO_CUTTING_BOARD`, `PLACE_CABBAGE`, `CHOP_CABBAGE`,
  `TAKE_FINISHED_FOOD`, `PUT_FOOD_ON_TABLE`, `TAKE_CLEAN_DISH`,
  `PLATE_AT_TABLE`, `TAKE_PLATED_FOOD`, `SUBMIT_ORDER` 각 단계의
  `side`, `offsetCol`, `offsetRow`, `rotate`, `bobX/bobY`.

구현 후에는 이 파일의 숫자만 바꾸면 된다. `offsetCol: 1`은 한 타일 오른쪽,
`offsetRow: -1`은 한 타일 위다. `bobX/bobY`는 화살표가 왕복할 방향과 거리다.

현재 고정 대화 화살표 좌표는 `app/globals.css`의 `.dialogue-arrow-*`, 행동 화살표는
`app/Game.tsx`의 `coachTarget` 타일 중심에서 자동 계산된다. 구현 때 이 두 곳의 숫자를
위 설정 파일로 옮긴다.

### 배치 규칙

- 설비는 첫 타일 중심이 아니라 전체 타일 범위를 기준으로 위·아래·좌·우 바깥쪽에 화살표를 붙인다.
- 맵 가장자리 설비는 화살표가 화면 밖으로 나가지 않도록 주방 안쪽 방향에 둔다.
- 중앙 테이블처럼 주변 에셋이 많은 대상은 단계별 `side` 값으로 빈 쪽을 고른다.
- `SELECT_EARTH`는 `offsetRow: -1`로 두어 푸름이 타일보다 한 타일 위에 표시한다.
- 첨부 화면의 턴 설명 화살표는 `dialogue.clock`의 위치를 시계 왼쪽·아래 바깥으로 옮기고
  시계를 향하게 회전한다.
- 화살표는 계속 보이되 대상 그림의 중심과 이동 경로를 덮지 않는다.

## 2. 다이얼로그와 하이라이트 레이어

현재는 대화 전체가 `z-index: 40`, 하이라이트된 우측 정보창이 `41`이라 정보창이
하단 대화창을 덮을 수 있다. `Dialogue`를 다음 세 레이어로 분리한다.

1. 어두운 막: 40
2. 하이라이트된 주문·시계·우측 정보창: 41
3. 화살표와 하단 대화창·이름표·초상: 42

이렇게 하이라이트는 살리되 대화창 위로 우측 창이 튀어나오지 않게 한다.

## 3. 퐁당이 등장과 자동 턴 전환

현재는 푸름이가 양배추를 써는 동작으로 행동력을 쓴 같은 턴 중간에 퐁당이가
공개된다. 그 뒤 퐁당이가 행동력을 쓰면 둘 다 0이므로 턴이 끝나 푸름이가
건너뛴 것처럼 보인다.

- `waterArrivalLines` 종료 시 현재 턴을 한 번만 정산하고 새 턴을 시작한다.
- 새 턴에서 푸름이와 퐁당이 모두 최대 행동력을 받는다.
- 튜토리얼의 `endTurn` 안내도 현재 대상만 보고 즉시 `finishTurn()`을 호출하지 않는다.
  먼저 공개된 다른 슬라임의 남은 행동력을 확인하고 자동 선택한다.
- 다른 슬라임에게 행동력이 있으면 턴 종료 화살표를 띄우지 않고, 전원이 행동했거나
  Space로 쉬기를 표시했을 때만 다음 턴으로 간다.

## 4. `나가기`와 쿠키 이어하기

### 저장 형식

`app/progress.ts`의 `localStorage` 구현을 브라우저 표준 `document.cookie`로 바꾼다. 의존성은
추가하지 않는다.

- 쿠키 이름: `nan2026.progress.v2`
- 값: URL encode한 `{ stars: StageProgress, resumeStageId: string | null }` JSON
- 속성: `Path=/; SameSite=Lax; Max-Age=31536000`
- 신뢰 경계: 스테이지 ID와 별 0~3을 현재 `defaultStages()`로 다시 검증한다.
- 기존 `nan2026.progress.v1` localStorage가 있고 쿠키가 없으면 한 번 쿠키로 옮겨 기존
  진행도를 잃지 않는다.

### 흐름

- 정산창의 `모드 선택` 버튼을 `나가기`로 바꾼다.
- 승리 후 나가거나 다음 스테이지 전환 전에 닫히면 `resumeStageId`는 다음 스테이지다.
- 패배 후 나가면 `resumeStageId`는 현재 스테이지다.
- 마지막 스테이지를 클리어하면 이어할 판이 없으므로 `resumeStageId`를 비운다.
- 아르바이트 모드 판을 누를 때 `resumeStageId`가 있으면 작은 확인창으로
  `이어하기` / `처음부터` / `취소`를 보여 준다.
- `이어하기`는 저장된 스테이지를 시작하고, `처음부터`는 튜토리얼부터 시작하되
  이미 받은 최고 별 기록은 유지한다.
- 스테이지 중간 상태 전체는 저장하지 않는다. 이어하기는 저장된 스테이지의 첫 턴부터다.

## 5. 먼 설비 클릭은 상호작용 시도

현재 `app/Game.tsx`는 선택한 슬라임이 설비 옆에 없으면 설비 정보만 열고
슬라임 선택을 풀어 버린다. 이 분기를 없앤다.

- 슬라임이 선택된 채 설비를 누르면 거리와 무관하게 `interactActor`를 호출한다.
- 멀면 코어의 기존 `옆 칸에 서야 합니다` 거절 문구를 토스트로 보여 준다.
- 슬라임 선택과 설비 정보창은 유지한다.
- 선택한 슬라임이 없을 때만 설비 정보 열기로 처리한다.
- 원격 자동 이동·자동 상호작용은 하지 않는다.

## 구현하지 않는 범위

- 화살표 에셋 교체·새 화살표 생성
- 튜토리얼 대사·레시피·맵 구조 변경
- 계정 동기화·서버 저장·쿠키 동의 팝업
- 스테이지 중간의 전체 `GameState` 저장
- 먼 설비로 자동 이동한 뒤 자동 상호작용

## 구현 순서

1. 화살표 배치 설정과 대상 외곽 앵커를 추가한다.
2. 대화창·하이라이트 레이어를 분리한다.
3. 퐁당이 등장 턴 경계와 전원 행동 후 자동 턴 종료를 보정한다.
4. 쿠키 저장과 이어하기 확인창, `나가기`를 구현한다.
5. 먼 설비 클릭을 상호작용 거절 흐름으로 연결한다.
6. 테스트·빌드 후 튜토리얼과 이어하기를 브라우저에서 직접 플레이한다.

## 완료 조건

### 화살표·레이어

- 모든 화살표가 대상 에셋과 이동 경로를 가리지 않고 바깥쪽에 표시된다.
- 푸름이 선택 화살표가 푸름이 타일보다 한 타일 위에 표시된다.
- 턴 설명 화살표가 시계를 가리지 않고 시계를 향한다.
- 우측 정보창은 어두운 막보다 앞에 있고, 하단 대화창은 정보창보다 앞에 있다.
- `app/tutorial-arrow-layout.ts`의 값만 바꿨을 때 화살표 좌표와 흔들림 방향이 바뀐다.

### 턴·이어하기

- 퐁당이 소개가 끝난 뒤 푸름이와 퐁당이의 행동력이 모두 최대치다.
- 한 슬라임이 행동력을 다 쓰더라도 다른 공개 슬라임이 행동할 수 있으면 턴이 넘어가지 않는다.
- 정산창에 `나가기`가 표시되고 `모드 선택`은 표시되지 않는다.
- 나갔다가 아르바이트 모드를 누르면 저장된 스테이지가 있을 때만 이어하기 확인창이 뜨고, 두 선택이 정확한 스테이지를 시작한다.
- 새로고침·브라우저 재시작 후에도 별과 이어할 스테이지가 쿠키에서 복구된다.
- 기존 localStorage 진행도는 첫 실행에 쿠키로 이관된다.

### 상호작용·검증

- 번개 슬라임이 원거리 설비를 누르면 설비 선택만 남지 않고 인접해야 한다는 토스트가 뜨며 번개 선택은 유지된다.
- 인접한 설비의 정상 상호작용과 선택하지 않은 상태의 설비 정보 열기는 기존대로다.
- 튜토리얼 화살표별 외곽 배치, 레이어 순서, 퐁당이 턴 경계, 쿠키 검증·이관,
  원거리 설비 거절을 각각 실행 가능한 테스트로 남긴다.
- `npm test`, `npm run lint`, `npm run build`, `npm run build:pages`를 통과한다.
- GitHub Pages에서 홈 → 튜토리얼 → 퐁당이 등장 → 정산 → 나가기 → 이어하기를 직접 플레이한다.

## 구현·검증 결과

`PASS`

- 화살표 조절값을 `app/tutorial-arrow-layout.ts`로 모았고 설비 전체 크기를 기준으로
  바깥쪽에 놓았다. 푸름이와 양배추 상자 화살표는 직접 화면에서 겹침이 없음을 확인했다.
- 퐁당이 등장 대사 종료 후 푸름이·퐁당이 모두 행동력 1을 받았고, 퐁당이만
  이동해도 턴이 지나지 않고 푸름이가 선택되었다.
- 양배추 제출까지 튜토리얼을 완주해 종료 대사, 정산, `나가기`, 쿠키 복구,
  `이어하기` / `처음부터` / `취소`, 1스테이지 도입 대사를 확인했다.
- 번개 슬라임으로 멀리 있는 양배추 상자를 누르면 선택을 유지한 채
  `옆 칸에 서야 합니다` 토스트와 설비 정보가 함께 나왔다.
- 테스트 55개, lint, 일반 빌드, GitHub Pages 정적 빌드를 통과했다.
