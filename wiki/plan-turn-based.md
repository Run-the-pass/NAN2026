# 턴제 전환 계획

**상태**: 구현·검증 완료(2026-08-06). 아래 범위를 모두 반영했다.
계획과 달라진 세 가지는 [실제 구현과 달라진 점](#실제-구현과-달라진-점)에 있다.

실시간 `tick(deltaMs)` 루프를 걷어내고 행동력 기반 턴 루프로 바꾼다.
추가보다 삭제가 큰 작업이다.

## 확정된 결정 (2026-08-06)

명세에 없어 사용자에게 확인한 항목이다.

| 항목 | 결정 |
|---|---|
| 재료 상자 자동 리필 | 1턴마다 1개 |
| 화재 | 후순위. 이번 범위에서 제외 |
| 화로·튀김기·믹서기 | 레시피가 없어 이번엔 만들지 않는다. 도마만 |
| 행동력이 모자란 조리 | 부분 소모 허용. 남은 AP만큼 진척도를 올리고 다음 턴에 이어서 한다 |
| 소모표에 없는 행동 | 집기·놓기·버리기·제출 각 1 AP, 소각하기 2 AP |
| 테이블 조합 결과 | 명세 11.3대로 **음식 담긴 그릇이 테이블에 남는다**. 지금은 슬라임이 계속 들고 가므로 바꾼다 |
| 자리 교환 금지 | 한 마리씩 순차 처리라 자동 성립. 별도 규칙을 넣지 않는다 |
| 기구 사용 조작 | 인접 칸에 선 슬라임으로 기구를 **좌클릭**. 기존 우클릭 상호작용을 이관 |
| 스테이지 턴 수·최소 주문 수 | 임시 검증값. 아래 열린 질문 참고 |

## 구현 범위

### 1. 행동력

- `ActorState`에 `actionPoints` / `maxActionPoints`. 전기 2, 나머지 1.
- 턴 시작 시 전원 `maxActionPoints`로 초기화. 턴 종료 시 잔여분은 소멸.
- `slimeTypes[].statLevels`(workSpeed·moveSpeed)와 `statTables`를 없앤다.
  이동·작업 속도가 행동력 하나로 통일되므로 남길 이유가 없다.

### 2. 이동

- 선택한 슬라임의 상·하·좌·우 1칸을 이동 가능 표시로 띄우고, 클릭하면 1 AP를
  쓰고 그 칸으로 간다.
- 벽·설비 칸·다른 슬라임이 점유한 칸은 표시 자체를 띄우지 않는다.
  명세 7절 충돌 규칙이 이 한 가지로 전부 해결된다.
- 삭제 대상: `routeBetween`, `segmentCrossesObstacle`, `routeLength`,
  `navigationHitboxes`, `statTables.moveTilesPerSecond`, `ActorIntent`,
  `ActorStatus`의 `MOVING`/`WAITING`, `moveActor`의 보간 루프.
- 슬라임의 진짜 위치는 타일이다. `x`/`y`는 렌더링에서 `tileCenter`로 만든다.

### 3. 행동력 소모

| 행동 | AP |
|---|---:|
| 1칸 이동 | 1 |
| 물건 집기 / 내려놓기 / 버리기 / 제출 | 1 |
| 도마 사용 | 2 |
| 세척기에 더러운 그릇 넣기 | 1 |
| 세척기에서 세척 | 2 |
| 소각기 소각 | 2 |

`workCost`·`workDurationFor`·`progressMs`/`totalMs`(ms)를 정수 AP 표로 바꾼다.

### 4. 조리·세척·소각 진척도

- 남은 AP만큼 진척도를 올린다. 필요량에 못 미치면 미완인 채로 남는다.
- 중단해도 진척도를 유지한다. `releaseWork`가 지금은 `progressMs`를 0으로
  되돌리는데, 이 초기화를 없앤다.
- 예: 땅 슬라임(1 AP)이 도마를 쓰면 2턴에 걸쳐 감자 하나를 썬다.

### 5. 기구별 속성 제한

| 기구 | 행동 | 속성 |
|---|---|---|
| 재료 상자 | 사용 | 전체 |
| 도마 | 사용 | 땅 |
| 소각기 | 버리기 | 전체 |
| 소각기 | 소각 | 불 |
| 세척기 | 넣기 | 전체 |
| 세척기 | 세척 | 물 |
| 테이블·그릇 생성대·제출대 | 사용 | 전체 |

도마는 지금 속성 제한이 없다. 땅 전용으로 막는다. 소각·세척은 이미 맞다.

### 6. 유효하지 않은 상호작용

- AP를 소모하지 않고 토스트로 이유를 띄운다.
- 기존 `refuse()`의 말풍선 아이콘을 토스트로 바꾼다. 거절 사유 문구는 이미
  있으므로 표시 방식만 교체한다.

### 7. 턴 루프

`tick(state, deltaMs)`를 `endTurn(state)`로 바꾼다.

1. 턴 시작 → 전원 행동력 초기화
2. 플레이어가 원하는 순서로 조작 (즉시 판정)
3. 턴 종료 버튼 → 잔여 AP 소멸
4. 재료 상자 1개 리필
5. 스테이지 남은 턴 1 감소, 0이면 스테이지 종료 판정

`GameState.timeLeft`/`timeLeftMs`, `Stage.timeLimitMs`를 `turnsLeft`/`turnLimit`로
바꾼다.

### 8. 주문과 스테이지 판정

- 동시 노출 주문 2개(`orderConfig.activeOrderCount: 3 → 2`).
- 스테이지별 레시피 리스트를 순서대로 소비한다. 하나 처리되면 다음이 채워진다.
- 다음 레시피 2개를 주문 카드 우측 상단에 작게 미리 보여 준다.
- `Stage`에 `requiredOrders`(통과 최소 주문 수)를 추가한다.
- 통과 판정: `filled >= requiredOrders`. 지금은 전 주문 완료만 통과라 바꾼다.
- 랭크: 기준 달성 별 1, +2건 별 2, +3건 별 3. 정산 화면에 표시한다.

### 9. 제거

| 대상 | 위치 |
|---|---|
| `Q`/`W`/`E`/`R`/`Space` 선택 조작 | `app/Game.tsx` 키 핸들러, 하단 선택키 UI |
| 주문 카드 시간 게이지 | `OrderCards`의 `urgency`·`left` |
| 슬라임 영입 화면 | `RecruitScreen`. 명세 14절이 4마리 고정·증감 없음이라 존재 이유가 없다 |
| 드래그 범위 선택·Shift 다중 선택 | 턴제는 한 마리씩 조작한다 |
| 남은 시간 기반 연출 | "마감 임박" 배너, 30초 러쉬 음악 전환 |

- **화재**: `advanceFires` 호출만 뺀다. `FireState`와 `canUseStation`의
  화재 분기는 그대로 두어 나중에 턴 단위로 되살릴 때 다시 안 쓰게 한다.

## 실제 구현과 달라진 점

계획서를 쓴 뒤 코드를 만지면서 바꾼 것들이다.

1. **화재 코드는 호출만 끊는 대신 시간 기반 부분을 지웠다.**
   `advanceFires`·`igniteStation`·진화 작업은 전부 `igniteAfterMs` 같은 ms
   값을 쓰고 있어 턴제에서는 그대로 되살릴 수 없었다. 남긴 것은 `FireState`,
   `fires` 상태, `fireConfig`, 그리고 "불이 난 설비는 사용할 수 없습니다"
   가드 하나다. 어차피 되살릴 때 턴 단위로 새로 써야 하는 코드였다.
2. **테이블 경유 내려놓기를 없앴다.** 손이 차서 못 하는 지시를 받으면 가까운
   빈 테이블에 먼저 내려놓고 원래 작업을 잇던 동작이다. 명세 5절이
   "물건을 들고 있는 상태에서 조리 등 다른 상호작용 시도 → 행동하지 않음"
   이라 정면으로 어긋난다. 지금은 토스트로 거절한다.
3. **스폰에 최소 간격(`SPAWN_SPACING` 3)을 넣었다.** 계획에 없던 것이다.
   턴제는 슬라임끼리 지나갈 수 없어서, 기존처럼 시작 지점에 붙여 세우면
   가운데 슬라임이 첫 턴부터 동료에게 막혀 한 칸도 못 움직였다.

## 열린 질문

- 스테이지별 턴 수와 통과 최소 주문 수. `1-1`~`1-3`에 임시값을 넣고
  펀테스트로 정한다.
- 스테이지별 레시피 리스트. 현재 레시피가 구운 감자 하나뿐이라 리스트가
  같은 항목의 반복이 된다. 음식이 늘어야 의미가 생긴다.
- 화재의 턴 기반 발화·전파 규칙.
- 턴제에서 번개(전기) 슬라임의 행동력 2가 유일한 차별점이 된다. 나머지
  셋의 역할 구분은 속성 제한 기구가 늘어야 살아난다.
