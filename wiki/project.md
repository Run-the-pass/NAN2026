# NAN 2026

## 한 문장

플레이어가 마우스와 키보드로 속성이 다른 슬라임을 선택·지휘해
구운 감자를 만들고 3분 동안 주문을 채우는 Phaser 3 펀테스트.

## 현재 플레이 흐름

```text
첫 속성 슬라임 선택
→ 좌클릭 또는 속성 키로 슬라임 선택
→ 그릇 생성대에서 깨끗한 그릇을 가져오고 재료 상자에서 감자 담기
→ 조리 도구를 우클릭해 감자 넣기
→ 아무 슬라임으로 조리하고 깨끗한 그릇에 구운 감자 담기
→ 제출대를 우클릭해 납품한 뒤 더러운 그릇을 물 슬라임으로 세척
```

- 새 조작 명령은 기존 작업을 교체한다.
- 슬라임은 `IDLE → MOVING → WORKING/WAITING → IDLE`을 실행한다.
- 슬라임은 재료가 없는 조리 도구 앞에서 기다리고, 감자가 들어오면 자동으로 작업한다.
- 조리 도구는 한 번에 한 마리만 작업하며 작업자와 진행도를 표시한다.
- 현재 소지품은 슬라임 위 아이콘으로 표시한다.

## 조작

- 좌클릭: 슬라임 한 마리 선택, 빈 바닥에서 선택 해제
- `Shift+좌클릭`: 선택 추가·제외, 빈 바닥 드래그: 범위 선택
- 바닥 우클릭: 선택된 슬라임이 설비 히트박스를 우회해 클릭한 유클리드 좌표까지 이동
- 설비 우클릭: 선택된 슬라임이 작업 타일로 이동한 뒤 상호작용
- `Q`: 물, `W`: 불, `E`: 번개, `R`: 땅 속성 전체 선택
- `Space`: 현재 조작 가능한 모든 슬라임 선택

슬라임 ID와 표시 이름은 물·불·번개·땅으로 통일한다. 각 속성은 식당
업무에 맞는 독립 스탯과 역할 설명을 가진다.

## 구현 원칙

- Phaser 3, TypeScript, 데스크톱 웹 브라우저를 사용한다.
- 브라우저와 이미 설치된 기능을 우선하며 새 의존성을 추가하지 않는다.
- 규칙과 상태 전이는 렌더링에서 분리해 CLI와 테스트에서 실행한다.
- 같은 seed, 스쿼드, 조작, 경과 시간은 같은 결과를 만든다.
- 기능은 계획, 작업, 검증 순서로 진행한다.

## 현재 구현

- 새 `슬라임 레스토랑` 로고와 기존 책상·가마솟·거품·슬라임 배치의 홈 화면
- 홈 장식을 뷰포트 전체에 배치하고 게임 프레임을 화면 끝까지 채우는 반응형
  레이아웃. 세로로 긴 화면은 식당 목재 배경으로 남는 영역을 연결한다
- 게임 중 홈 이동은 상시 버튼 대신 설정 모달 안에서만 제공한다
- 홈·인게임 상단 음악 설정 탭, 음악 켜기·끄기·음량 저장
- 외곽 조리대와 중앙 작업 섬으로 구성된 16×10 주방 맵, 첫 직원 선택
- 게임 코어와 화면이 함께 읽는 단일 맵 데이터와 `127.0.0.1` 전용 맵
  에디터. `edit-map.sh`로 실행하며 설비·상호작용 칸·스폰을 검증한 뒤
  원자적으로 저장한다
- 설비는 `종류@열,행` 좌표 ID를 가지며 같은 종류를 여러 개 배치해도 보관물,
  작업자·진행도와 화재가 서로 섞이지 않는다. 작업 위치는 위→왼쪽→오른쪽→
  아래 순서로 자동 선택하고 에디터에서 설비 ID별로 고정할 수 있다
- `deploy.sh`로 현재 변경을 검증한 뒤 기존 Codex Sites 프로젝트에 자동 배포한다.
  원문인 `raw/`의 수정·미추적 파일은 배포 커밋에서 제외한다
- 속성·이동/작업 속도가 다른 슬라임 4종
- 좌클릭·Shift·드래그 선택, `Q/W/E/R/Space` 그룹 선택, 선택 링
- 우클릭 속도 기반 유클리드 이동, 고정 설비와 `#` 벽 타일 충돌 영역 우회,
  설비 상호작용
- 재료 상자·조리 도구·소각장의 한 타일 정사각형 표시와 60×60 타일 전체
  우클릭 상호작용 판정
- y좌표 기반 슬라임·설비 깊이 정렬, 설정 중 정지와 `3 → 2 → 1` 재개
- 감자 자동 생성, 속성 제한 없는 단일 작업자 조리, 재료 대기·자동 재개
- 조리 도구 상태·작업자·진행도, 구운 감자 운반·제출
- 테이블 위에 도마를 올린 조리 도구, 감자를 올린 재료 상자, 빈 접시 위에
  음식을 얹은 주문 카드
- 판 시작 "영업 시작", 30초 이하 "마감 임박", 정산 "영업 종료"·"게임 오버"
  문구 이미지
- 인게임 얼굴의 눈 크기를 원본 아트에 맞춰 키운다. 불은 원본 삼각형을
  키우고 더 기울인다. 눈 위치와 간격은 원본 그대로다
- 설비 이름은 상시 표시하지 않는다. 상태만 타일 위에 남긴다
- 홈은 문서 스크롤과 고무줄 튕김을 막고, 설정 창이 홈 메뉴 위로 열린다
- 네 슬라임 선택 카드의 몸통 크기·탄성 주기 정렬. 번개·땅·불 원본 SVG의
  장식을 보존하고 인게임 숨쉬기·걷기·작업 모션과 좌우 반전을 적용한다
- 고유 그릇 3개 생성, 그릇에 담긴 음식만 제출, 제출 후 오염, 물 슬라임
  세척과 재사용 순환
- 그릇·재료를 한 칸 보관하는 테이블, 땅 슬라임 그릇 2개 운반, 생성대·
  세척기·테이블 상태 표시
- 홈·일반 영업 음악, 남은 시간 30초 이하 러쉬 음악, 패배 결과 음악
- UI·라운드·주문·조리·설거지·운반·화재·슬라임 선택과 이동 효과음
- 주문 목록 기반 주문 시스템: 라운드 주문 주입, 활성 주문 표시,
  `ItemId` 대조 제출 판정, 주문에 없는 음식 처리, 라운드 성공·실패 판정
- 상단 전용 영역의 최대 3개 주문 카드와 라운드 HUD. 맵은 카드 아래에서
  시작하며 낮은 가로 화면에서는 주문 카드를 왼쪽 세로 레일로 옮긴다
- 하단 `Q/W/E/R/Space` 선택키와 선택 링. 슬라임 상세 패널은 선택할 때
  자동으로 열지 않고 한 마리 선택 뒤 `정보` 버튼으로만 연다
- 맵을 덮지 않는 우측 전용 레일의 슬라임·설비 정보 패널과 게임을 멈추는
  설비 상세 도움말. Phaser 맵은 남은 영역의 왼쪽에 정렬한다
- 캐릭터 선택, 상단 주문·HUD, 정보·설정과 게임 오버 화면은 검보라 웹 패널
  대신 식당의 목재·철제·종이 재질과 각진 판형을 사용한다
- 조리 도구 화재: 조리 완료 방치 발화, 사용 차단, 인접 설비 전파,
  물 슬라임 5초 진화와 진행도 표시
- 인스턴스 ID 기반 슬라임. 같은 속성을 여러 마리 데려올 수 있고 속성
  키는 그 속성의 모든 마리를 고른다
- 원본 번개·땅·불 슬라임의 머리 장식을 제외한 몸통 크기를 물 슬라임과
  맞추고, 물 슬라임 기준의 눈·입 간격, 이동 방향별 얼굴·등 표시, 정지·이동 중
  깜빡임을 적용한다. 불 눈은 공통 눈보다 20% 크고 원의 윗부분을 사선으로 자른 형태다
- `1-1`~`1-3` 기본 스테이지 루프, 스테이지 HUD, 성공·실수 횟수와 누적
  골드 정산, 다음 스테이지·재시작·타이틀 이동
- 첫 직원 선택 뒤와 스테이지 정산 뒤 표시되는 전환 정보 화면. 실제 16×10
  주방 맵, TIP 2개, 3×2 음식 슬롯과 공용 레시피 기반 제작 흐름을 표시하며
  화면이 열린 동안 게임 상태와 타이머를 멈춘다
- 주문 실수는 횟수만 세고 골드를 깎지 않으며, 죽음·화재 감점·점수·랭킹은
  정산에서 제외
- 골드, 3분 라운드, D1 플레이 요약
- 신뢰 경계와 상태 전이를 검증하는 결정론 코어 테스트·CLI

주문·화재의 미확정 규칙은 `game/core.ts`의 `orderConfig`, `fireConfig`
상수로 분리했다. 범위와 기본값은
[주문 시스템·화재 시스템 계획](plan-orders-and-fire.md)에 있다.

## 현재 제외·열린 질문

- 이동 진형·슬라임 간 충돌·동적 장애물, 작업 예약 큐
- 다른 설비의 속성 규칙, 카메라 조작
- **설비를 종류마다 여러 대 놓기**: 2026-08-03 결정으로 하기로 했으나 아직
  구현하지 않았다. 지금은 상태가 종류당 하나뿐이라(`state.table` 등) 테이블을
  두 대 놓으면 내용물이 섞인다. 맵 검증도 `정확히 한 칸`을 강제한다.
  설계는 [작업대 여러 대 계획](plan-multi-station.md) 참고
- 불 슬라임의 고유 능력: 조리 도구의 불 속성 요구가 빠지면서 소각만 남았다.
  번개도 이동 속도 외에 고유 능력이 없어 두 속성의 역할을 다시 정해야 한다
- 감자 외 음식: 현재 레시피는 구운 감자 하나뿐이라 주문의 `foodId` 대조가
  실질적으로 한 종류만 오간다
- 점수 시스템과 랭킹: 2026-08-02 결정으로 넣지 않는다. 정산 합계 자리에는
  기존 골드를 쓴다
- 화재로 인한 골드 차감: 2026-08-02 결정으로 넣지 않고 정산에도 올리지
  않는다. 화재의 페널티는 설비를 못 쓰는 것과 진화 부담뿐이다
- 죽음을 발생시키는 규칙과 부활 시스템: 2026-08-02 결정으로 넣지 않는다
- 현재 `1-1`~`1-3`의 번호·이름·주문·제한 시간과 정보 화면 TIP은 기본
  검증값이다. 실제 작업이 필요한 로딩·클리어 후 영입 화면과 스쿼드 5마리
  이상 배치는 아직 규칙과 화면 흐름이 확정되지 않았다
  ([추가본 정리](../raw/추가본_정리/02_확정과_미정.md))
- 주문 10초 간격 유입과 주문별 제한 시간·실패 상태. 현재 주문 카드는 전역
  영업 시간을 표시하고 `orderConfig.activeOrderCount`만 3으로 둔다
- 라운드 사이 업그레이드·성장 선택
- 화재 진압 후 설비 복구 시간: 규칙이 없어 구현하지 않았다
- `fireConfig.igniteAfterMs` 12초는 실제 플레이에서 조리 완료 직후
  바로 불이 나는 편이다. 펀테스트로 값을 정해야 한다
- `dishConfig`의 초기 그릇 3개, 세척 4초, 땅 슬라임 2개 운반, 테이블
  1칸, 드래그 8px은 첫 검증값이며 수치 확정이 필요하다
- 여러 칸 테이블의 직접 슬롯 선택, 음식 폐기 뒤 그릇 복구, Shift+단축키,
  드래그 경계 판정은 원문에서 미정이라 구현하지 않았다
