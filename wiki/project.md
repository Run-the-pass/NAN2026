# NAN 2026

## 한 문장

플레이어가 마우스와 키보드로 속성이 다른 슬라임을 선택·지휘해
버섯 구이를 만들고 3분 동안 주문을 채우는 Phaser 3 펀테스트.

## 현재 플레이 흐름

```text
첫 속성 슬라임 선택
→ 좌클릭 또는 속성 키로 슬라임 선택
→ 그릇 생성대에서 깨끗한 그릇을 가져오고 재료 상자에서 버섯 담기
→ 조리 도구를 우클릭해 버섯 넣기
→ 불 슬라임으로 조리하고 깨끗한 그릇에 버섯 구이 담기
→ 제출대를 우클릭해 납품한 뒤 더러운 그릇을 물 슬라임으로 세척
```

- 새 조작 명령은 기존 작업을 교체한다.
- 슬라임은 `IDLE → MOVING → WORKING/WAITING → IDLE`을 실행한다.
- 불 슬라임은 재료가 없는 조리 도구 앞에서 기다리고, 버섯이 들어오면 자동으로 작업한다.
- 조리 도구는 한 번에 한 마리만 작업하며 작업자와 진행도를 표시한다.
- 현재 소지품은 슬라임 위 아이콘으로 표시한다.

## 조작

- 좌클릭: 슬라임 한 마리 선택, 빈 바닥에서 선택 해제
- `Shift+좌클릭`: 선택 추가·제외, 빈 바닥 드래그: 범위 선택
- 바닥 우클릭: 선택된 슬라임이 설비 히트박스를 우회해 클릭한 유클리드 좌표까지 이동
- 설비 우클릭: 선택된 슬라임이 작업 타일로 이동한 뒤 상호작용
- `Q`: 물, `W`: 불, `E`: 번개, `R`: 땅 속성 전체 선택
- `Space`: 현재 조작 가능한 모든 슬라임 선택

슬라임 ID와 표시 이름은 물·불·번개·땅으로 통일한다. 각 속성은 식당
업무에 맞는 독립 스탯과 역할 설명을 가진다.

## 구현 원칙

- Phaser 3, TypeScript, 데스크톱 웹 브라우저를 사용한다.
- 브라우저와 이미 설치된 기능을 우선하며 새 의존성을 추가하지 않는다.
- 규칙과 상태 전이는 렌더링에서 분리해 CLI와 테스트에서 실행한다.
- 같은 seed, 스쿼드, 조작, 경과 시간은 같은 결과를 만든다.
- 기능은 계획, 작업, 검증 순서로 진행한다.

## 현재 구현

- 새 `슬라임 레스토랑` 로고와 기존 책상·가마솟·거품·슬라임 배치의 홈 화면
- 홈 장식을 뷰포트 전체에 배치하고 게임 프레임을 화면 끝까지 채우는 반응형
  레이아웃. 세로로 긴 화면은 식당 목재 배경으로 남는 영역을 연결한다
- 게임 중 홈 이동은 상시 버튼 대신 설정 모달 안에서만 제공한다
- 홈·인게임 상단 음악 설정 탭, 음악 켜기·끄기·음량 저장
- 고정 식당 주방 맵, 첫 직원 선택
- 속성·이동/작업 속도가 다른 슬라임 4종
- 좌클릭·Shift·드래그 선택, `Q/W/E/R/Space` 그룹 선택, 선택 링
- 우클릭 속도 기반 유클리드 직선 이동과 설비 상호작용
- 홈·인게임 중앙 음악 설정 모달, 음악 켜기·끄기·음량 저장
- 고정 식당 주방 맵, 첫 직원 선택
- 속성·이동/작업 속도가 다른 슬라임 4종
- 좌클릭·Shift·드래그 선택, `Q/W/E/R/Space` 그룹 선택, 선택 링
- 우클릭 속도 기반 유클리드 이동, 고정 설비 히트박스 우회와 설비 상호작용
- y좌표 기반 슬라임·설비 깊이 정렬, 설정 중 정지와 `3 → 2 → 1` 재개
- 버섯 자동 생성, 단일 불 슬라임 조리, 속성 거부, 재료 대기·자동 재개
- 조리 도구 상태·작업자·진행도, 버섯 구이 운반·제출
- 물·불 선택 카드의 몸통 크기·탄성 주기 정렬, 불 원본 SVG의 인게임
  숨쉬기·걷기·작업 모션과 좌우 반전
- 고유 그릇 3개 생성, 그릇에 담긴 음식만 제출, 제출 후 오염, 물 슬라임
  세척과 재사용 순환
- 그릇·재료를 한 칸 보관하는 테이블, 땅 슬라임 그릇 2개 운반, 생성대·
  세척기·테이블 상태 표시
- 홈·일반 영업 음악, 남은 시간 30초 이하 러쉬 음악, 패배 결과 음악
- UI·라운드·주문·조리·설거지·운반·화재·슬라임 선택과 이동 효과음
- 주문 목록 기반 주문 시스템: 라운드 주문 주입, 활성 주문 표시,
  `ItemId` 대조 제출 판정, 주문에 없는 음식 처리, 라운드 성공·실패 판정
- 조리 도구 화재: 조리 완료 방치 발화, 사용 차단, 인접 설비 전파,
  물 슬라임 5초 진화와 진행도 표시
- 골드, 3분 라운드, D1 플레이 요약
- 신뢰 경계와 상태 전이를 검증하는 결정론 코어 테스트·CLI

주문·화재의 미확정 규칙은 `game/core.ts`의 `orderConfig`, `fireConfig`
상수로 분리했다. 범위와 기본값은
[주문 시스템·화재 시스템 계획](plan-orders-and-fire.md)에 있다.

## 제거된 범위

- 약초·물약·스크롤, 마법진, 이전 종류명과 스탯 프리셋
- 스크롤 작업대와 두 색 자원 제작 데이터
- 음성 입력, STT, Gemini 명령 해석, 음성 결과 UI, 호출명 선택
- 청력·집중력 스탯과 명령 접수 판정
- 음성 실험실과 음성 API

## 현재 제외·열린 질문

- 이동 진형·슬라임 간 충돌·동적 장애물, 작업 예약 큐
- 다른 설비의 속성 규칙, 카메라 조작, 상세 오브젝트 정보 화면
- 죽음을 발생시키는 규칙과 부활 시스템
- 주문 10초 간격 유입 (동시 주문 수는 `orderConfig.activeOrderCount`로 열림)
- 라운드 사이 업그레이드·성장 선택
- 화재 진압 후 설비 복구 시간: 규칙이 없어 구현하지 않았다
- `fireConfig.igniteAfterMs` 12초는 실제 플레이에서 조리 완료 직후
  바로 불이 나는 편이다. 펀테스트로 값을 정해야 한다
- `dishConfig`의 초기 그릇 3개, 세척 4초, 땅 슬라임 2개 운반, 테이블
  1칸, 드래그 8px은 첫 검증값이며 수치 확정이 필요하다
- 여러 칸 테이블의 직접 슬롯 선택, 음식 폐기 뒤 그릇 복구, Shift+단축키,
  드래그 경계 판정은 원문에서 미정이라 구현하지 않았다
