# NAN 2026

## 한 문장

플레이어가 음성으로 불완전하지만 성장하는 슬라임들에게 명령하여 식당을 운영하고, 점차 더 추상적인 명령을 사용할 수 있게 되는 Phaser 3 웹 게임.

## 핵심 플레이 루프

```text
말한다 → 슬라임이 이해하고 행동한다 → 성격·숙련도에 따른 문제가 보인다
→ 원인을 파악해 다시 지시한다 → 성장 후 더 짧고 추상적으로 명령한다
```

실수는 무작위 방해가 아니라 배고픔, 낮은 숙련도, 제한된 기억력처럼 플레이어가 관찰하고 예측할 수 있는 원인에서 발생한다.

## 시연의 성장 증명

시연 전반부에는 단일 행동을 각각 명령한다.

```text
"말랑아 버섯 가져와."
```

강화 후에는 동일한 결과를 더 추상적인 명령 하나로 달성한다.

```text
"말랑아 재료 준비해."
```

최소 시연은 이 전후 차이가 실제 플레이에서 분명하게 보이면 성공한다.

## 최소 범위

- 고정된 식당 맵
- 주방 슬라임과 서빙 슬라임
- 버섯 스튜 레시피 1개와 주문 1종
- 짧은 라운드 시작과 종료
- 단일 행동 명령
- 복합 또는 팀 명령 1종
- 관찰 가능한 성격·숙련도 실수 1종
- 강화 전후 명령 추상화 변화
- 오디오에서 Gemini 명령 JSON 생성
- Firebase 배포

대규모 스킬트리, 다수의 콘텐츠, 장기 육성, 멀티플레이, 완전 자율 AI는 범위 밖이다.

## 명령 책임 경계

```text
마이크 → 오디오 → Gemini → 후보로 제한된 명령 JSON
→ 게임 상태 검증 → 결정론적 작업 분해 → 게임 실행
```

Gemini는 의도를 구조화한다. 게임 코드는 허용된 actor, action, target을 검증하고 실제 작업 순서와 결과를 결정한다. 자막은 디버깅용이며 명령 입력으로 재사용하지 않는다.

## 구현 원칙

- Phaser 3, TypeScript, 데스크톱 웹 브라우저를 사용한다.
- 브라우저와 Phaser의 기본 기능을 우선하고 새 의존성은 실제 필요가 확인될 때만 추가한다.
- 규칙과 상태 전이는 렌더링에서 분리하여 그래픽 없이 검증할 수 있게 한다.
- 동일 입력과 랜덤 시드는 동일 결과를 만든다.
- 기능은 계획, 작업, 검증 순서로 진행한다.

## 제작 순서

1. Phaser 기본 맵과 슬라임
2. 명령 JSON으로 슬라임 이동
3. 재료 가져오기와 손질
4. 오디오에서 명령 JSON 생성
5. 조리와 요리 완성
6. 주문과 서빙
7. 복합 명령
8. 강화 전후의 명령 변화
9. 라운드 진행
10. Firebase 배포와 시연 안정화

## 현재 구현

- Phaser 3의 16×10 고정 타일 식당 맵과 플레이어, 말랑·빨강 슬라임
- 코어와 렌더러가 공유하는 60px 타일, 통행 가능 바닥, 벽·작업대 충돌
- 고정 순서 BFS 경로와 이동 속도를 이용한 슬라임의 장애물 우회 이동
- 한글 라벨로 구분되는 재료·손질·조리·서빙 구역
- 라운드 시작 주문 1건과 이후 10초마다 추가되는 버섯 스튜 주문
- 버섯 스튜 `GET → CHOP → COOK → SERVE` 흐름
- 버섯 상자·패스·슬라임 중 하나로 추적되는 음식 위치와 화면 아이콘·HUD 소지 표시
- `SERVE` 시 패스에서 완성된 스튜를 픽업한 뒤 고객에게 이동하는 두 구간 동선
- 슬라임별 FIFO 작업 큐와 `IDLE → MOVING → WORKING → IDLE` 상태
- 이동·작업 속도에 따라 코어가 계산하는 위치와 완료 시점
- 1라운드의 배고픔 사고와 재지시
- 라운드 사이 중앙 3장 성장 선택: 말랑 숙련, `PREPARE` 해금, 전체 강화
- `PREPARE` 선택 후 2라운드 `GET → CHOP` 추상 명령
- 오디오를 Gemini 명령 JSON으로 변환하는 API와 서버 allowlist 검증
- 같은 seed·입력·시간으로 위치, 큐, 주문, 점수를 재현하는 렌더링 독립 코어 테스트
- 그래픽 없이 명령을 실행하고 경과 시간·행동 결과·최종 상태·점수를 JSON으로 출력하는 CLI
- 시간, 점수, 주문 수, 다음 주문, 슬라임 상태·현재 작업·큐, 최근 상황 HUD
- Firebase Hosting 최소 설정과 Sites 배포 설정

## 결정

- 첫 시연의 관찰 가능한 실수는 배고픈 말랑이가 첫 버섯을 먹는 행동이다.
- 첫 추상 명령은 `PREPARE`이며 `GET → CHOP`으로 분해한다.
- 시연 라운드는 75초, 라운드당 버섯 스튜 1개 판매가 성공 조건이다.
- 주문은 라운드 시작 시 1건, 이후 플레이 중 10초마다 1건 추가한다.
- 명령은 즉시 결과를 바꾸지 않고 슬라임별 FIFO 작업 큐에 들어간다.
- 슬라임은 이동과 작업을 마친 뒤 결과를 적용하고, 큐가 비면 `IDLE`이 된다.
- 완성된 스튜는 패스에 놓이며, 서빙 슬라임이 패스에서 픽업한 뒤 고객에게 전달해야 판매된다.
- 음식 위치는 `버섯 상자`, `패스`, `말랑`, `빨강` 중 하나로 추적한다.
- 플레이어 직접 이동은 WASD와 방향키로 제공한다.
- 식당은 16×10, 칸당 60px의 단일 타일 데이터로 정의하며 코어와 Phaser가 이를 함께 사용한다.
- 경로가 여러 개면 `위 → 오른쪽 → 아래 → 왼쪽` 순서의 BFS로 결정해 재현성을 유지한다.
- 팀 명령은 현재 시연에서 제외한다.

## 남은 외부 설정

- 실제 음성 명령에는 배포 환경의 `GEMINI_API_KEY`가 필요하다.
- Firebase 프로젝트 선택과 Hosting 배포는 프로젝트 ID가 정해진 뒤 수행한다.
