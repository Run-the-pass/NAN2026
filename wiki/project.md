# NAN 2026

## 한 문장

플레이어가 첫 직원 슬라임에게 음성으로 물품과 목적지를 지시하고,
붉은·파란 약초를 물약 또는 스크롤로 가공해 3분 동안 주문을 채우는
Phaser 3 펀테스트.

## 현재 플레이 흐름

```text
첫 직원 슬라임 선택 (4종 중 1마리)
→ 붉은·파란 소환진에서 약초 자동 생성
→ "쫑긋아, 붉은 약초를 양조기에 넣어"
→ 양조기는 물약, 마법 테이블은 스크롤 생산
→ 주문 물품을 제출대에 납품
```

- 맵에는 선택된 슬라임, 약초 소환진 2개, 양조기, 마법 테이블,
  제출대와 쓰레기통이 있다.
- 각 슬라임은 독립 FIFO 큐로 `IDLE → MOVING → WORKING`을 실행한다.
- 스탯 4종이 활성이다: 작업 속도(작업 시간 배율), 이동 속도(타일/초),
  청력(플레이어와의 명령 가능 거리), 집중력(큐 한도).
- 청력 밖 명령은 `NOT_HEARD`, 한도 초과는 `TOO_COMPLEX`/`QUEUE_FULL`로
  거절하고 슬라임 위에 아이콘을 표시한다.
- 소환진은 색별 약초를 최대 4개까지 자동 생성한다. 양조기와 테이블은
  공용 재고를 최대 3개 보관한다.
- 약초의 색이 결과물 색을 결정하고, 목적지가 물약/스크롤 형태를 결정한다.
- 주문 1건을 완료하면 다음 주문이 이어지며, 납품한 물품은 현재 주문에서
  차감된다.
- 잘못된 물품 경로 또는 가득 찬 목적지는 상태를 바꾸지 않고 이유를 알린다.

이전 마도서 제작 펀테스트는 [기존 기준 문서](fun-test.md)에 보존한다.

## 명령 책임 경계

```text
스페이스바 푸시투토크
→ Web Speech 지원: 브라우저 STT → 로컬 문구 매칭
→ Web Speech 미지원: 원본 오디오 → Gemini
→ 후보로 제한된 명령 JSON
→ 게임 코어의 청력·집중력·순서·상태 검증 → Phaser 실행
```

- actor는 이번 판에 선택된 슬라임(`nerd`, `swift`, `keen`, `worker`
  중 스쿼드)만 허용한다. 이름이 불리지 않으면 첫 슬라임이다.
- item은 붉은·파란 약초/물약/스크롤 6종만 허용한다.
- target은 붉은·파란 소환진, 양조기, 마법 테이블, 제출대,
  쓰레기통만 허용한다.
- 명령 하나는 `물품 + 목적지`다. 코어가 물품 위치로 이동, 집기,
  목적지 이동, 투입을 큐에 구성한다.
- `그거/들고 있는 거/가지고 있는 거 + 목적지`는 예외적으로 지목한
  슬라임의 현재 소지품을 상태에서 확인하고, 진행 중 목적지를 양조기·
  마법 테이블·제출대·쓰레기통 중 말한 곳으로 바꾼다. 실제 소지품의
  허용 경로는 코어가 검증하며, 음성 실험실에서는 열두 조합을 각각
  기대 문장으로 선택·저장한다.
- 청력은 명령 확정 순간의 플레이어·슬라임 위치로 게임 코어가 판정한다.
- Gemini는 의도를 구조화할 뿐 작업 성공 여부와 결과를 정하지 않는다.
- Gemini는 들은 문장을 `transcript`로 함께 반환한다. 표시용이며 명령
  해석에는 사용하지 않는다. 해석 불가면 `status: UNKNOWN`과 이유를
  반환하고 게임은 실행하지 않는다.
- UI는 음성 실패를 세 단계로 구분해 보여 준다: 인식 실패, 해석 실패
  (들은 문장 표시), 접수(해석된 슬라임·행동·대상 표시). 상태 불가는
  최근 상황과 슬라임 알림 아이콘으로 표시한다.

## 구현 원칙

- Phaser 3, TypeScript, 데스크톱 웹 브라우저를 사용한다.
- 브라우저와 이미 설치된 기능을 우선하며 새 의존성을 추가하지 않는다.
- 규칙과 상태 전이는 렌더링에서 분리해 CLI와 테스트에서 실행한다.
- 동일한 seed, 스쿼드, 명령, 경과 시간은 동일한 결과를 만든다.
- 기능은 계획, 작업, 검증 순서로 진행한다.

## 현재 구현

- `/` 홈 화면과 `/game` 게임 화면 분리, 양방향 이동
- 홈 v2의 배경·SVG 로고·시작·설정·공방 소품 배치와 반응형 화면
- SVG 슬라임 휴식 모션, 포션 기포, 가마솥 수축·팽창 모션
- 참고 이미지 배치의 고정 공방 맵과 좌측 시간·골드 배지, 우측 패널 UI
- 시작 전 첫 직원 선택 화면 (4종 중 1마리, 코어·CLI는 1~3마리 지원)
- 주문·설비 재고 HUD, 기본 접힘 디버그, 플레이어 옆 첫 스폰
- 슬라임 4종의 스탯 레벨과 중앙 레벨 표 (배율·타일/초·거리·큐 한도)
- 슬라임별 독립 큐, 속도 기반 BFS 이동, 청력 원, 알림 아이콘, 호버 카드
- 플레이어(WASD)의 위치와 발화 음량에 따른 소리 원이 청력 판정 기준
- 플레이어가 E키로 앞의 설비를 직접 조작
- 소환진 자동 생성, 양조기·테이블 가공, 설비 공용 재고와 폐기
- 현재 든 물품을 지시어로 참조해 쓰레기통으로 운반을 전환하는 폐기 명령
- 소환진·양조기·테이블·제출대·쓰레기통을 구분하는 전용 실루엣과
  각 설비 앞 작업 위치 표시
- 순차 주문 생성, 주문 납품, 골드, 시간 만료와 재시작
- STT 문구를 로컬 사전으로만 매칭한다. 불일치 텍스트를 Gemini로 다시
  분석하지 않으며, Web Speech 미지원 시에만 원본 오디오를 Gemini로 보낸다.
  슬라임 이름과 물품·목적지의 자주 뭉개지는 발음은 명시적 별칭으로 매칭
- 스페이스바를 누르는 동안만 녹음하고, 뗄 때 해석하는 푸시투토크
- `/voice-lab`에서 대상·유효 작업을 조합해 실제 발화의 브라우저 STT와
  로컬 사전 결과를 D1에 저장한다. 감지 표현→표준 의미, 최근 기록, CSV,
  2단계 확인 후 개별 삭제를 제공
- 같은 코어를 실행하는 CLI(액터 접두사·PLAYER 위치)와 결정론 테스트
- 한 판이 끝나면 요약 지표를 D1에 저장하는 플레이테스트 기록 API

## 현재 제외

- 주문 실패 패널티, 가격 차등, 복수 주문 동시 표시
- 라운드 사이 업그레이드·성장 선택 (버프 표시 자리만 존재)
- 팀 명령의 역할 분담, 복수 레시피, 복수 맵, 장기 성장, 저장

이전 프로토타입 구현 이력은 [작업 로그](log.md)에만 보존한다.

## 열린 질문

- 음성인식 논의 문서(§9, §12)는 첫 펀테스트에서 청력·집중력을
  고정값으로 두고 슬라임 1마리를 쓰자고 제안했으나, 2026-07-25 사용자
  지시로 스탯 4종 활성화와 1~3마리 선택이 먼저 구현됐다. 사용자 지시가
  우선하므로 현재 구현을 유지하되, 펀테스트에서 낮은 청력·집중력이
  음성 경험 평가를 흐리는지 관찰이 필요하다.
- 주문 목표 수와 승리 조건은 현재 펀테스트에서 추가 조정이 필요하다.
- 사용자가 요청한 10초 간격 주문 유입은 아직 구현되지 않았다.

## 남은 외부 설정

- 실제 음성 명령에는 배포 환경의 `GEMINI_API_KEY`가 필요하다.
  키가 없으면 스페이스바 음성 입력이 503 안내를 표시하고 디버그 버튼으로
  시연한다.
