# NAN 2026

## 한 문장

플레이어가 시작 전에 고른 첫 직원 슬라임에게 음성으로 이름을 불러
마도서 제작을 지시하고, 슬라임별 스탯과 두 솥의 타이밍을 관리하여
3분 안에 마도서 8권을 납품하는 Phaser 3 펀테스트.

## 현재 플레이 흐름

```text
첫 직원 슬라임 선택 (4종 중 1마리)
→ "쫑긋아 약초 가져와" (이름 지휘)
→ 솥에 약초 넣기 → 젓기 → 5초 조합
→ 양피지 가져오기 → 담그기 → 5초 각인
→ 마도서 꺼내기 → 납품 (+100G)
```

- 맵에는 선택된 슬라임들, 약초 상자, 양피지 상자, 솥 2개, 납품대가
  있다. 가구는 종류마다 한 타일만 차지한다.
- 각 슬라임은 독립 FIFO 큐로 `IDLE → MOVING → WORKING`을 실행한다.
- 스탯 4종이 활성이다: 작업 속도(작업 시간 배율), 이동 속도(타일/초),
  청력(플레이어와의 명령 가능 거리), 집중력(큐 한도).
- 청력 밖 명령은 `NOT_HEARD`, 한도 초과는 `TOO_COMPLEX`/`QUEUE_FULL`로
  거절하고 슬라임 위에 아이콘을 표시한다.
- 두 솥은 각각 독립적인 상태와 5초 타이머를 가진다 (작업 속도 미적용).
- 잘못된 순서의 작업은 재료·솥·납품 상태를 바꾸지 않고 이유를 알린다.
- 180초 안에 8권을 납품하면 즉시 성공하고, 시간이 끝나면 실패한다.
  골드는 납품당 100G 적립되는 표시용 점수다.

자세한 범위와 보류 항목은 [3분 마도서 제작 펀테스트](fun-test.md)를
따른다.

## 명령 책임 경계

```text
마이크 → 오디오 + 스쿼드 → Gemini → 후보로 제한된 명령 JSON
→ 게임 코어의 청력·집중력·순서·상태 검증 → Phaser 실행
```

- actor는 이번 판에 선택된 슬라임(`nerd`, `swift`, `keen`, `worker`
  중 스쿼드)만 허용한다. 이름이 불리지 않으면 첫 슬라임이다.
- action은 `GET_HERB`, `ADD_HERB`, `MIX`, `GET_PARCHMENT`,
  `DIP_PARCHMENT`, `TAKE_BOOK`, `SUBMIT`만 허용한다.
- target은 현재 상자, 두 솥, 납품대 중 action에 맞는 대상만 허용한다.
  솥 작업은 미지정(null)도 허용하며, 실행 시점에 작업 상태가 맞는 솥을
  우선해 가까운 솥을 코어가 고른다.
- 청력은 명령 확정 순간의 플레이어·슬라임 위치로 게임 코어가 판정한다.
- Gemini는 의도를 구조화할 뿐 작업 성공 여부와 결과를 정하지 않는다.
- Gemini는 들은 문장을 `transcript`로 함께 반환한다. 표시용이며 명령
  해석에는 사용하지 않는다. 해석 불가면 `status: UNKNOWN`과 이유를
  반환하고 게임은 실행하지 않는다.
- UI는 음성 실패를 세 단계로 구분해 보여 준다: 인식 실패, 해석 실패
  (들은 문장 표시), 접수(해석된 슬라임·행동·대상 표시). 상태 불가는
  최근 상황과 슬라임 알림 아이콘으로 표시한다.

## 구현 원칙

- Phaser 3, TypeScript, 데스크톱 웹 브라우저를 사용한다.
- 브라우저와 이미 설치된 기능을 우선하며 새 의존성을 추가하지 않는다.
- 규칙과 상태 전이는 렌더링에서 분리해 CLI와 테스트에서 실행한다.
- 동일한 seed, 스쿼드, 명령, 경과 시간은 동일한 결과를 만든다.
- 기능은 계획, 작업, 검증 순서로 진행한다.

## 현재 구현

- `/` 홈 화면과 `/game` 게임 화면 분리, 양방향 이동
- 홈 v2의 배경·SVG 로고·시작·설정·공방 소품 배치와 반응형 화면
- SVG 슬라임 휴식 모션, 포션 기포, 가마솥 수축·팽창 모션
- 참고 이미지 배치의 고정 공방 맵과 좌측 시간·골드 배지, 우측 패널 UI
- 시작 전 첫 직원 선택 화면 (4종 중 1마리, 코어·CLI는 1~3마리 지원)
- 레시피·목표 패널, 기본 접힘 디버그, 플레이어 옆 첫 스폰
- 슬라임 4종의 스탯 레벨과 중앙 레벨 표 (배율·타일/초·거리·큐 한도)
- 슬라임별 독립 큐, 속도 기반 BFS 이동, 청력 원, 알림 아이콘, 호버 카드
- 플레이어(WASD)의 위치가 청력 판정 기준
- 두 솥의 독립 상태 전이와 자동 타이머, 미지정 시 가까운 솥 자동 배정
- 180초 제한, 8권 성공, 납품당 100G, 시간 만료 실패와 재시작
- 오디오와 스쿼드를 Gemini 명령 JSON으로 바꾸는 API와 서버 allowlist
- 라운드 시작부터 종료까지 켜지는 음성 대기와 말이 끝난 뒤 자동 전송
- 같은 코어를 실행하는 CLI(액터 접두사·PLAYER 위치)와 결정론 테스트
- 한 판이 끝나면 요약 지표를 D1에 저장하는 플레이테스트 기록 API

## 현재 제외

- 골드의 승리 조건화, 가격 차등, 금전 패널티
- 라운드 사이 업그레이드·성장 선택 (버프 표시 자리만 존재)
- 팀 명령의 역할 분담, 복수 레시피, 복수 맵, 장기 성장, 저장

이전 프로토타입 구현 이력은 [작업 로그](log.md)에만 보존한다.

## 열린 질문

- 음성인식 논의 문서(§9, §12)는 첫 펀테스트에서 청력·집중력을
  고정값으로 두고 슬라임 1마리를 쓰자고 제안했으나, 2026-07-25 사용자
  지시로 스탯 4종 활성화와 1~3마리 선택이 먼저 구현됐다. 사용자 지시가
  우선하므로 현재 구현을 유지하되, 펀테스트에서 낮은 청력·집중력이
  음성 경험 평가를 흐리는지 관찰이 필요하다.
- 연속 명령(한 문장 여러 행동)은 Gemini 스키마가 최대 6개까지 허용하나
  검증 실험(A: 단일 행동만 / B: 연속 허용)은 아직 계획 단계다.

## 남은 외부 설정

- 실제 음성 명령에는 배포 환경의 `GEMINI_API_KEY`가 필요하다.
  키가 없으면 마이크 버튼이 503 안내를 표시하고 디버그 버튼으로
  시연한다.
