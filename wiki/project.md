# NAN 2026

## 한 문장

플레이어가 속성이 다른 슬라임 4마리를 한 마리씩 골라 행동력을 나눠 쓰며
정해진 턴 안에 구운 감자 주문을 채우는 턴제 Phaser 3 펀테스트.

## 현재 플레이 흐름

```text
네 속성 슬라임을 모두 데리고 시작
→ 슬라임을 좌클릭해 고르고 상하좌우 표시가 뜬 칸으로 한 칸씩 이동
→ 재료 상자 옆에 서서 감자 집기
→ 도마 옆에 서서 감자를 올리고, 땅 슬라임이 행동력 2를 들여 썰기
→ 구운 감자를 집어 그릇 생성대에서 접시에 담기
→ 제출대 옆에 서서 제출하고, 더러워진 접시는 세척기에 넣어 물 슬라임이 세척
→ 할 일이 끝나면 턴 종료
```

- 이동과 행동은 모두 **행동력** 하나로 계산한다. 턴이 시작될 때 채워지고
  턴이 끝나면 남은 만큼 사라진다.
- 슬라임끼리 같은 칸에 설 수 없다. 이동 가능 표시가 점유된 칸을 빼므로
  자리 교환도 자연히 막힌다.
- 조리·세척·소각은 행동력이 모자라면 넣은 만큼만 진척도가 오르고 다음
  턴에 이어서 한다. 중단해도 진척도는 남는다.
- 유효하지 않은 상호작용은 행동력을 쓰지 않고 토스트로 이유를 알려 준다.
- 현재 소지품은 슬라임이 앞으로 든 것처럼 보여 준다. 등을 돌리면 몸 뒤로
  넘어가 위쪽만 보인다.

## 조작

- 슬라임 좌클릭(또는 하단 슬라임 버튼): 한 마리 선택. 다시 누르면 해제
- 선택하면 상하좌우 한 칸에 이동 가능 표시가 뜬다. 벽·설비 칸과 다른
  슬라임이 선 칸, 행동력이 없을 때는 표시가 뜨지 않는다
- 이동 가능 표시 좌클릭: 그 칸으로 한 칸 이동(행동력 1)
- 설비 좌클릭: 정보 패널을 열고, 고른 슬라임이 옆 칸에 서 있으면 사용한다
- 빈 바닥 좌클릭: 선택 해제
- `턴 종료` 버튼: 남은 행동력을 버리고 다음 턴으로 넘어간다
- `Esc`: 설정 창

한 번에 한 마리만 고른다. 슬라임 ID와 표시 이름은 물·불·번개·땅으로
통일하고, 속성을 가르는 수치는 턴당 행동력 하나뿐이다.

### 행동력

| 슬라임 | 턴당 행동력 |
|---|---:|
| 번개(전기) | 2 |
| 물·불·땅 | 1 |

| 행동 | 소모 |
|---|---:|
| 한 칸 이동 | 1 |
| 물건 집기·놓기·버리기·제출 | 1 |
| 도마 썰기 | 2 |
| 그릇 세척 | 2 |
| 소각 | 2 |

### 기구별 속성 제한

| 기구 | 행동 | 속성 |
|---|---|---|
| 도마 | 썰기 | 땅 |
| 세척기 | 세척 | 물 |
| 소각기 | 소각 | 불 |
| 그 외 전부 | 물건 집기·놓기 포함 | 제한 없음 |

## 구현 원칙

- Phaser 3, TypeScript, 데스크톱 웹 브라우저를 사용한다.
- 브라우저와 이미 설치된 기능을 우선하며 새 의존성을 추가하지 않는다.
- 규칙과 상태 전이는 렌더링에서 분리해 CLI와 테스트에서 실행한다.
- 같은 seed, 스쿼드, 조작, 경과 시간은 같은 결과를 만든다.
- 기능은 계획, 작업, 검증 순서로 진행한다.

## 현재 구현

- 새 `슬라임 레스토랑` 로고와 기존 책상·가마솟·거품·슬라임 배치의 홈 화면
- 홈 장식을 뷰포트 전체에 배치하고 게임 프레임을 화면 끝까지 채우는 반응형
  레이아웃. 세로로 긴 화면은 식당 목재 배경으로 남는 영역을 연결한다
- 게임 중 홈 이동은 상시 버튼 대신 설정 모달 안에서만 제공한다
- 홈·인게임 상단 소리 설정 탭. 왼쪽 스피커 아이콘이 켜기·끄기를 겸하고
  오른쪽이 음량이다. 음악과 효과음을 따로 조절해 저장한다
- 손이 차서 지금 못 하는 지시를 받으면 가까운 빈 테이블에 먼저 내려놓고
  원래 작업을 이어서 한다
- 낱개 음식을 들고 그릇 생성대에 가면 빈 접시를 꺼내 그 자리에서 담는다
- 외곽 조리대와 중앙 작업 섬으로 구성된 14×8 주방 맵. 첫 판은 네 속성을
  모두 데리고 시작하며 고르는 화면은 없다
- 맵에는 코드로 덧그린 장식·광원 원·작업칸 점을 두지 않고 바닥·벽·실제
  설비만 상시 표시한다
- 게임 코어와 화면이 함께 읽는 단일 맵 데이터와 `127.0.0.1` 전용 맵
  에디터. `edit-map.sh`로 실행하며 설비·상호작용 칸·스폰을 검증한 뒤
  원자적으로 저장한다
- 설비는 `종류@열,행` 좌표 ID를 가지며 같은 종류를 여러 개 배치해도 보관물,
  작업자·진행도와 화재가 서로 섞이지 않는다. 작업 위치는 위→왼쪽→오른쪽→
  아래 순서로 자동 선택하고 에디터에서 설비 ID별로 고정할 수 있다
- `deploy.sh`로 현재 변경을 검증한 뒤 기존 Codex Sites 프로젝트에 자동 배포한다.
  원문인 `raw/`의 수정·미추적 파일은 배포 커밋에서 제외한다
- 슬라임은 맵의 영업 시작 지점에서 가까운 빈 바닥으로 퍼져 서되 서로
  최소 3칸 떨어진다. 붙여 세우면 턴제에서 안쪽 슬라임이 동료에게 막혀
  첫 턴부터 갇힌다. 에디터에서는 시작 지점 한 칸만 찍는다
- 턴당 행동력이 다른 슬라임 4종. 번개만 2고 나머지는 1이다
- 한 마리 선택과 선택 링, 인접 4칸 이동 표시, 하단 슬라임별 행동력 표시와
  `턴 종료` 버튼
- 상하좌우 한 칸 이동과 슬라임 충돌. 벽·설비 칸과 점유된 칸은 이동
  후보에서 빠진다
- 설비 옆 칸에 선 슬라임만 그 설비를 쓴다
- 재료 상자·도마·소각기의 한 타일 정사각형 표시와 60×60 타일 전체
  우클릭 상호작용 판정
- y좌표 기반 슬라임·설비 깊이 정렬, 설정 중 정지와 `3 → 2 → 1` 재개
- 턴마다 감자 1개 리필, 땅 슬라임 전용 도마 썰기, 여러 턴에 걸치는 진척도
- 도마 상태와 진행도 표시, 완성 음식은 낱개로 회수하되 제출은 깨끗한 접시만 가능
- 테이블 위 도마, 감자를 올린 재료 상자, 빈 접시 위에
  음식을 얹은 주문 카드
- 판 시작 "영업 시작", 30초 이하 "마감 임박", 정산 "영업 종료"·"게임 오버"
  문구 이미지
- 인게임 얼굴의 눈 크기를 원본 아트에 맞춰 키운다. 불은 눈을 더 키우고 더
  기울이며 입도 크다. 눈 위치와 간격은 원본 그대로다
- 작업량은 정수 행동력이다. 남은 행동력만큼만 진척도가 오르고 모자라면
  다음 턴에 이어서 한다. 조리·세척·소각이 모두 이 규칙을 탄다
- 유효하지 않은 상호작용은 행동력을 쓰지 않고 화면 아래 토스트로 이유를
  알려 준다
- 설비 이름 외에 내부 키·좌표는 화면에 표시하지 않는다
- 설비 이름은 상시 표시하지 않는다. 상태만 타일 위에 남긴다
- 홈은 문서 스크롤과 고무줄 튕김을 막고, 설정 창이 홈 메뉴 위로 열린다
- 네 슬라임 선택 카드의 몸통 크기·탄성 주기 정렬. 번개·땅·불 원본 SVG의
  장식을 보존하고 인게임 숨쉬기·걷기·작업 모션과 좌우 반전을 적용한다
- 고유 그릇 3개 생성, 깨끗한 접시만 제출, 사용 접시 오염,
  물 슬라임 세척과 재사용 순환
- 소각기는 설비별로 최대 5개까지 쓰레기를 버리고, 불 슬라임의 소각 작업으로
  비운다. 가득 찼을 때 불 슬라임이 오면 물건을 들고 있어도 소각부터 하며,
  거절할 때는 가득 참·소각할 것 없음을 구분해 알려 준다
- 그릇·재료를 한 칸 보관하고 감자와 빈 접시를 순서와 무관하게 합치는
  테이블, 땅 슬라임 그릇 2개 운반, 생성대·세척기·테이블 상태 표시
- 홈·일반 영업 음악, 남은 턴 10 이하 러쉬 음악, 패배 결과 음악
- UI·라운드·주문·조리·설거지·운반·화재·슬라임 선택과 이동 효과음
- 스테이지별 레시피 목록을 순서대로 소비하는 주문 시스템. 동시에 2건을
  노출하고 다음 레시피 2개를 주문 카드 옆에 작게 미리 보여 준다
- 통과 기준(`requiredOrders`) 이상을 처리하면 스테이지 통과. 기준만 채우면
  별 1개, 2건 더 처리하면 별 2개, 3건이면 별 3개
- 상단 전용 영역의 주문 카드 2장과 턴 HUD. 시간 게이지는 없다
- 슬라임 한 마리를 선택하면 우측 상세 패널을 즉시 열며 남은 행동력을 보여 준다
- 맵을 덮지 않는 우측 전용 레일의 슬라임·설비 정보 패널과 게임을 멈추는
  설비 상세 도움말. Phaser 맵은 남은 영역의 왼쪽에 정렬한다
- 캐릭터 선택, 상단 주문·HUD, 정보·설정과 게임 오버 화면은 검보라 웹 패널
  대신 식당의 목재·철제·종이 재질과 각진 판형을 사용한다
- 인스턴스 ID 기반 슬라임. 같은 속성을 여러 마리 데려올 수 있고 속성
  키는 그 속성의 모든 마리를 고른다
- 원본 번개·땅·불 슬라임의 머리 장식을 제외한 몸통 크기를 물 슬라임과
  맞추고, 물 슬라임 기준의 눈·입 간격, 이동 방향별 얼굴·등 표시, 정지·이동 중
  깜빡임을 적용한다. 불 눈은 공통 눈보다 20% 크고 원의 윗부분을 사선으로 자른 형태다
- `1-1`~`1-3` 기본 스테이지 루프와 턴 제한, 스테이지 HUD, 성공·실수
  횟수와 누적 골드 정산, 랭크 별 표시, 다음 스테이지·재시작·타이틀 이동
- 판 시작 전과 스테이지 정산 뒤 표시되는 전환 정보 화면. 실제 14×8
  주방 맵, TIP 2개, 3×2 음식 슬롯과 공용 레시피 기반 제작 흐름을 표시하며
  화면이 열린 동안 게임 상태와 타이머를 멈춘다
- 주문 실수는 횟수만 세고 골드를 깎지 않으며, 죽음·화재 감점·점수·랭킹은
  정산에서 제외
- 골드, 턴 제한 라운드, D1 플레이 요약
- 신뢰 경계와 상태 전이를 검증하는 결정론 코어 테스트·CLI

주문의 미확정 규칙은 `game/core.ts`의 `orderConfig`, 행동력 수치는
`actionPointsPerTurn`·`actionCost`, 속성 제한은 `stationElements`로 분리했다.
턴제 전환 범위와 확정된 결정은 [턴제 전환 계획](plan-turn-based.md)에 있다.

## 제거된 범위

- 약초·물약·스크롤, 마법진, 이전 종류명과 스탯 프리셋
- 스크롤 작업대와 두 색 자원 제작 데이터
- 음성 입력, STT, Gemini 명령 해석, 음성 결과 UI, 호출명 선택
- 청력·집중력 스탯과 명령 접수 판정
- 음성 실험실과 음성 API
- 실시간 진행: `tick(deltaMs)` 루프, 유클리드 경로 탐색과 히트박스 우회,
  이동·작업 속도 스탯, 초 단위 제한 시간
- `Q`/`W`/`E`/`R`/`Space` 선택키, Shift·드래그 다중 선택, 여러 마리 동시 지시
- 주문 카드의 남은 시간 게이지
- 스테이지 사이 슬라임 영입 화면. 명세 14절대로 4마리로 고정한다
- 손이 차면 가까운 테이블에 먼저 내려놓고 원래 작업을 잇던 경유 동작.
  명세 5절이 "물건을 든 채 다른 상호작용은 행동하지 않음"이라 어긋난다
- 도마 화재의 방치 발화·전파·진화. 후순위로 미뤘다
