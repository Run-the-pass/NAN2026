# 3분 마도서 제작 펀테스트

## 현재 목표

음성으로 슬라임들에게 이름을 불러 여러 단계 작업을 지시하고, 두 솥의
진행 상태와 타이밍, 슬라임별 스탯 차이를 관리하는 행위가 재미있는지
검증한다.

```text
3분 안에 마도서 8권 납품
```

## 현재 범위

- 고정 마법 공방 맵 1개 (참고 이미지 기반 배치)
- 시작 전 선택 화면에서 4종 중 첫 직원 슬라임 1마리 선택
  (코어와 CLI는 1~3마리를 지원하며 다마리 확장은 후속 테스트용)
- 음성으로 이름을 불러 개별 지휘 (이름이 없으면 첫 슬라임)
- 스탯 4종(작업 속도·이동 속도·청력·집중력) 레벨 0~5 활성
- 약초 상자, 양피지 상자, 솥 2개, 납품대 1개 — 각 한 타일
- 솥별 5초 조합과 5초 각인 (작업 속도 미적용)
- 완성된 마도서 회수와 납품, 납품당 100G 적립 (표시용 점수)
- 작업 상태·명령 인식 결과·청력 범위 피드백

## 슬라임 종류 (스탯 문서 기준)

| 종류 | 작업 | 이동 | 청력 | 집중 |
|---|---:|---:|---:|---:|
| 너드 | 2 | 0 | 1 | 3 |
| 날쌘 | 1 | 3 | 1 | 1 |
| 쫑긋 | 1 | 1 | 3 | 1 |
| 일꾼 | 3 | 1 | 0 | 2 |

- 작업 속도: 기본 작업 시간 ÷ 레벨 배율 (0.70~1.75배)
- 이동 속도: 초당 1.6~3.1타일
- 청력: 명령 확정 순간 플레이어와의 유클리드 거리 2~7타일. 범위 밖은
  `NOT_HEARD`로 버려지고 슬라임 위에 아이콘이 잠시 표시된다.
- 집중력: 기억 가능한 원자 작업 1~6개. 명령 자체가 한도를 넘으면
  `TOO_COMPLEX`, 남은 공간이 부족하면 `QUEUE_FULL`로 거절한다.

## 원자 명령

`GET_HERB`, `ADD_HERB`, `MIX`, `GET_PARCHMENT`,
`DIP_PARCHMENT`, `TAKE_BOOK`, `SUBMIT`만 허용한다.

actor는 이번 판에 선택된 슬라임(`nerd`, `swift`, `keen`, `worker` 중
스쿼드)만 허용한다. 솥 작업은 `cauldron-01`, `cauldron-02` 또는
미지정(null)을 허용한다. 미지정이면 실행 시점에 작업 상태가 맞는 솥을
우선해 경로가 가장 짧은 솥을 코어가 고른다. 동률이면 고정 순서상 앞의
솥을 골라 결정론을 지킨다. Gemini는 이 허용 목록 안에서 의도만
구조화하고, 순서 검증과 결과는 게임 코어가 결정한다.

## 현재 비활성

- 반복 주문과 주문별 제한 시간
- 서빙 역할과 손님 동선
- 골드의 승리 조건화, 가격 차등, 고용비, 금전 패널티
- 라운드 사이 업그레이드와 성장 선택 (버프 표시 자리만 존재)
- 팀 명령의 역할 분담, 복수 레시피, 추상화 명령

## 구현 상태

- 16×10 공방 맵. 가구는 종류마다 한 타일만 차지하고 작업 타일은
  가구와 상하좌우로 인접한 바닥이다.
- 시작 전 첫 직원 선택 화면 (포트레이트, 특성, 스탯 게이지)
- 슬라임별 독립 큐·이동·작업 속도, 청력 원 표시, 알림 아이콘
- 독립 상태와 타이머를 가진 솥 2개와 미지정 시 자동 배정
- 좌측 남은 시간·획득 골드 배지, 우측 상태 패널 (참고 이미지 배치)
- 슬라임 호버 카드: 일러스트, 이름, 특성, 스탯 게이지, 받은 버프
- 180초 제한과 8권 납품 성공 판정, 납품당 100G
- 동일 코어를 사용하는 디버그 버튼, Gemini 명령, CLI 테스트
- 음성 피드백 카드: 들은 문장(transcript), 해석된 슬라임·행동·대상,
  인식 실패/해석 실패/접수 구분
- 레시피·목표 패널과 기본 접힘 디버그 버튼. 첫 슬라임은 플레이어 옆에서
  시작해 첫 명령이 청력 범위 안에 들어온다.
