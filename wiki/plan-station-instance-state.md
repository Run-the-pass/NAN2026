# 설비 인스턴스 상태·작업 위치 계획

## 범위

- 같은 종류의 설비를 여러 칸에 놓을 수 있게 하고 각 설비의 보관물·작업자·
  진행도·화재를 서로 독립시킨다.
- 설비 인스턴스 ID는 맵 좌표를 붙인 `종류@열,행` 형식으로 만든다.
  예: 현재 기본 맵의 테이블은 `table@7,1`이다.
- 게임 화면에서 클릭한 설비 인스턴스 ID를 이동 의도와 상태 전이까지
  보존한다.
- 작업 위치는 설비에 붙은 바닥을 위, 왼쪽, 오른쪽, 아래 순서로 찾아
  자동 결정한다. 맵의 `taskTiles`에 해당 인스턴스 ID가 있으면 그 위치를
  우선한다.
- 맵 에디터에서 같은 설비를 여러 번 배치하고, 선택한 설비 인스턴스의
  작업 위치만 선택적으로 고정할 수 있게 한다.

## 구현하지 않는 범위

- 작업 위치 예약 큐, 슬라임끼리의 충돌, 여러 슬라임의 동시 작업 배정
- 좌표 변경 뒤 이전 인스턴스 상태를 이어 가는 런타임 맵 마이그레이션
- 배포 사이트에서 맵을 편집하는 기능

## 결정

- 열과 행은 맵 데이터와 같은 0부터 시작하는 좌표를 쓴다.
- 설비 종류는 레시피·아이콘·설명용으로만 유지하고, 실제 상태 키에는
  설비 인스턴스 ID만 쓴다.
- 자동 작업 위치를 만들 수 없거나 둘 이상의 설비가 같은 작업 위치를
  쓰면 맵 저장과 빌드를 거부한다.
- 설비 종류별 최소 한 개 배치는 현재 게임 흐름을 위해 계속 요구한다.

## 완료 조건

- 같은 종류 설비를 둘 이상 둔 맵이 검증·저장되고 서로 다른 인스턴스 ID를
  갖는다.
- 한 테이블·조리 도구·세척기·그릇 생성대의 내용이나 진행도를 바꿔도 같은
  종류의 다른 설비 상태가 바뀌지 않는다.
- 설비 우클릭은 그 설비의 작업 위치로 이동하고 다른 같은 종류 설비를
  사용하지 않는다.
- 작업 위치 미지정 시 위→왼쪽→오른쪽→아래 규칙이 결정론적으로 적용되고,
  인스턴스 ID로 지정한 위치가 있으면 자동값보다 우선한다.
- 코어 테스트, 맵 검증, lint, 프로덕션 빌드와 에디터 동작 검수를 통과한다.

## 검증 결과

- **PASS**. 기본 맵에 `table@7,1`과 `table@5,5`를 함께 두고 서로 다른
  물건을 보관해도 상태가 섞이지 않는 회귀 검사를 통과했다.
- 작업 위치 고정값과 `table@5,5`의 자동 위쪽 칸 `(5,4)`을 확인했다.
- 로컬 에디터에서 세 번째 테이블을 놓자 `table@6,6 · 자동` 선택 항목이
  생기는 것을 확인했으며 검수 변경은 저장하지 않았다.
- 코어 테스트 32/32, 맵 검증, lint, 프로덕션 빌드와 `git diff --check`를
  통과했다.
