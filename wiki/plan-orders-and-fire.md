# 주문 시스템·화재 시스템 계획

담당 분리 문서에 따라 주문과 화재만 구현한다. 슬라임 선택·이동·상호
작용 조작과 조리 흐름은 수정하지 않고 그 위에 얹는다.

## 결정

- 주문은 `{ id, foodId, targetCount, submittedCount }` 목록으로 관리하고
  라운드 시작 시 외부에서 주입할 수 있다. 이름 문자열이 아니라 `ItemId`로
  대조한다.
- 현재 `order.need`/`order.done` 맵과 고정 목표 5는 주문 목록으로
  대체한다. `filled`는 완료된 주문 수, `goal`은 라운드 주문 수가 된다.
- 화재는 설비별 `{ neglectMs, onFire, workerId, extinguishMs, spreadMs }`
  상태로 관리하고, 화재 대상으로 지정된 설비에만 상태를 만든다.
- 방치 판정은 지금 상호작용 상태를 가진 유일한 설비인 조리 도구에만
  적용한다. 다른 설비가 상태를 갖게 되면 분기를 추가한다.
- 인접 판정은 바닥 타일이 아니라 `displayTiles`의 설비 배치 거리로 한다.
- 진화는 물 속성만 가능하다. 다른 속성이 불난 설비에 도착하면 기존 속성
  거부 경로에서 작업 불가로 처리한다.
- 기존 골드는 이번 범위에서 건드리지 않는다. 주문 판정은 골드와 무관하게
  동작한다.

## 미정 → 설정값

명세 18항의 미정 사항은 규칙을 확정하지 않고 `orderConfig`,
`fireConfig` 상수로 분리한다. 기본값은 현재 게임 동작을 그대로 유지하는
값이다.

| 미정 사항 | 설정 키 | 기본값 |
|---|---|---|
| 동시 존재 주문 수 | `orderConfig.activeOrderCount` | `1` |
| 잘못된 음식 제출 처리 | `orderConfig.invalidSubmission` | `"reject"` |
| 목표 조기 달성 시 즉시 종료 | `orderConfig.endRoundWhenOrdersDone` | `true` |
| 화재 대상 설비 | `fireConfig.flammableStations` | `["stove"]` |
| 방치 판정 시작 시점 | `fireConfig.neglectStatus` | `"COMPLETE"` |
| 화재 발생까지 시간 | `fireConfig.igniteAfterMs` | `12000` |
| 화재 전파 간격 | `fireConfig.spreadIntervalMs` | `6000` |
| 인접 판정 거리 | `fireConfig.spreadRange` | `1` |
| 대각선 전파 | `fireConfig.spreadDiagonal` | `false` |
| 진화 중단 시 진행도 유지 | `fireConfig.keepExtinguishProgress` | `false` |

`invalidSubmission`은 `"reject"`(거부하고 음식 유지)와 `"discard"`(음식
제거) 두 가지만 구현한다. 명세가 나열한 `제출 거부`와 `음식 유지`는 이
게임에서 같은 결과이고, `별도의 실패 처리`는 규칙이 정의되지 않았다.

## 남은 미정 항목

- 화재 진압 후 설비 복구 시간: 규칙이 없어 설정도 코드도 만들지 않는다.
- 현재 맵에는 화재 대상 설비가 조리 도구 하나뿐이라 실제 플레이에서
  전파가 일어나지 않는다. 전파는 설정으로 대상을 늘려 검증한다.

## 구현 범위

1. `game/core.ts`에 `Order` 타입, 주문 목록, 주입 시 신뢰 경계 검증,
   `activeOrders`·`orderComplete`·`roundResult`를 추가한다.
2. 제출 판정을 주문 대조로 바꾸고 잘못된 음식은 설정대로 처리한다.
3. 시간 만료 판정을 `roundResult`로 바꾼다.
4. 설비 화재 상태, 방치 발화, 인접 전파, 물 속성 5초 진화와 진행도를
   `tick`과 상호작용 경로에 넣는다.
5. 불난 설비는 진화 외의 모든 상호작용을 시작할 수 없게 한다.
6. `app/Game.tsx`에 활성 주문의 음식·목표·제출 수·완료 여부와 조리 도구
   화재·진화 진행도를 표시한다. UI는 상태를 읽기만 한다.
7. 게임 제목을 `슬라임 레스토랑`으로 맞춘다.

## 구현하지 않는 범위

- 새 레시피·조리 과정·제출대 그래픽·라운드 정비·다음 라운드 미리보기
- 보상, 돈, 주문 실패 패널티
- 바닥 타일 화재, 캐릭터 발화, 체력·사망·연기 피해, 소화기, 자동 소화
- 화재로 인한 골드 차감

## 완료 조건

- 주문 목록을 주입해 라운드를 시작할 수 있고 활성 주문의 음식·목표·제출
  수·완료 여부가 화면에 보인다.
- 올바른 음식 제출이 진행도를 올리고, 주문에 없는 음식은 설정대로
  거부되거나 제거되며 진행도를 올리지 않는다.
- 모든 주문을 채우면 성공, 시간이 끝났는데 남으면 실패로 판정한다.
- 조리 완료된 조리 도구를 방치하면 불이 나고 그 뒤 상호작용이 막힌다.
- 물 슬라임이 5초 상호작용하면 불이 꺼지고 설비를 다시 쓸 수 있다.
- 다른 속성 슬라임의 진화 시도는 작업 불가로 처리된다.
- 설정으로 화재 대상을 늘리면 인접 설비로 전파되고 바닥으로는 번지지
  않는다.
- 결정론 테스트, 린트, 프로덕션 빌드가 통과한다.
