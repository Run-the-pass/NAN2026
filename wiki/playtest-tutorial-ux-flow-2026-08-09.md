# 튜토리얼 조작 흐름·UX 플레이테스트 보고서

## 의도한 흐름

튜토리얼은 한 번에 한 목표만 화살표로 표시하되, 공개된 다른 슬라임의 이동은
막지 않는다. 행동력을 다 쓴 슬라임 다음에는 행동 가능한 슬라임이 자동 선택되고,
모두 행동하거나 `Space`로 쉬면 다음 턴으로 자동 전환한다.

| 순서 | 목표 | 완료 상태 |
|---|---|---|
| 1 | 푸름이 선택과 상세 정보 확인 | 푸름이 선택 |
| 2 | 첫 이동과 행동력 설명 | 턴 종료·슬라임 선택 버튼 노출 |
| 3 | 양배추 상자 이동·획득 | 푸름이가 양배추 소지 |
| 4 | 도마 이동·놓기·손질 | 도마에 채썬 양배추 완성 |
| 5 | 퐁당이 등장과 접시 획득 | 퐁당이가 깨끗한 접시 소지 |
| 6 | 푸름이 음식 회수·테이블 전달 | 테이블에 채썬 양배추 |
| 7 | 퐁당이 접시 합치기·완성 접시 회수 | 퐁당이가 완성 접시 소지 |
| 8 | 제출대 제출·종료 대사 | 정산 창 표시 |

퐁당이의 접시 획득을 음식 전달보다 앞에 둔다. 등장 위치가 그릇 상자 앞인데도
상자를 누를 수 없던 이전 흐름보다 화면에 보이는 상황과 실제 허용 행동이 일치한다.

## UI 배치 원칙

- 행동력 설명은 하단 왼쪽의 슬라임 선택 버튼과 턴 종료 버튼을 남겨 두고 그
  오른쪽에 표시한다. 설명 중 슬라임 선택 버튼은 금색으로 강조한다.
- 짧은 행동 안내는 우측 정보 창이 아니라 하단 HUD의 빈 공간에 표시한다.
- 지도 화살표는 Phaser 캔버스보다 높은 DOM 레이어에 두고, 현재 목표가 바뀔
  때만 새 위치를 계산한다.
- 잘못된 튜토리얼 설비는 상태를 바꾸지 않고 조용히 무시한다. 삭제 요청한
  `노란색 화살표가 가리키는 곳부터` 토스트는 표시하지 않는다.
- 게임 화면의 글자는 선택하지 못하고 이미지의 브라우저 기본 드래그도 막는다.

## 검증 시나리오와 결과

검증 환경은 Pages 정적 빌드, Chromium 1280×720이다. 모드 선택부터 튜토리얼
정산까지 마우스와 `Space`로 직접 플레이했다.

| 검증 항목 | 결과 | 확인 내용 |
|---|---|---|
| 행동력 설명 배치 | PASS | 푸름이 버튼과 턴 종료 버튼이 모두 보이고 푸름이 버튼이 강조됨 |
| 짧은 안내 배치 | PASS | 우측 상세 정보 내용은 유지되고 안내는 하단 빈 공간에 표시됨 |
| 화살표 레이어 | PASS | 도마·그릇 상자·테이블 화살표가 맵 배경보다 앞에 표시됨 |
| 테이블 화살표 충돌 | PASS | 퐁당이를 테이블 오른쪽으로 접근시켜도 합치기·회수 화살표가 두 슬라임과 이동 칸을 가리지 않음 |
| 접시 획득 | PASS | 퐁당이 등장 직후 그릇 상자를 눌러 접시를 정상 획득함 |
| 이후 조리 흐름 | PASS | 음식 전달 → 합치기 → 회수 → 제출 → 종료 대사 → 정산까지 완주함 |
| 자동 턴 | PASS | 두 슬라임을 번갈아 움직이고 남은 슬라임을 쉬게 하면 턴이 자동 전환됨 |
| 차단 토스트 제거 | PASS | 첫 이동 단계에서 다른 설비를 눌러도 토스트 0개, 턴·행동력 불변 |
| 선택·드래그 방지 | PASS | `body`·이미지 `user-select:none`, 이미지 `-webkit-user-drag:none` 확인 |

## 반복 플레이 기록

1. 첫 완주에서는 잘못된 설비·이동 방향·조기 턴 종료를 눌러 상태와 화살표가
   유지되는지 확인했다. 다른 슬라임을 먼저 움직이거나 `Space`로 쉬어도 두
   슬라임의 행동력이 따로 처리되고 자동 턴이 정상 동작했다.
2. 퐁당이를 테이블 오른쪽으로 접근시키자 `PLATE_AT_TABLE`과
   `TAKE_PLATED_FOOD` 화살표가 퐁당이 몸을 덮는 문제를 발견했다.
3. 두 화살표를 테이블 아래 왼쪽 외곽의 고정 좌표로 옮겼다. 단계가 유지되는
   동안 좌표를 다시 계산하지 않는 원칙은 그대로다.
4. 수정 빌드를 처음부터 다시 플레이했다. 같은 오른쪽 접근 경로에서도 화살표가
   퐁당이·푸름이·이동 칸을 가리지 않았고, 접시 획득부터 종료 대사와 정산까지
   다시 완주했다. 정산의 최종 표시는 주문 성공 1번, 남은 턴 82턴이었다.

## 자동 검증

- `npm test`: 58/58 PASS. 접시 획득이 음식 회수보다 먼저 나오는 상태 순서를 검증한다.
- `npm run typecheck`: PASS
- `npm run lint`: PASS
- `npm run build:pages`: PASS. 기존 Next 캐시 손상 뒤 `.next`·`.vinext`를
  임시 백업하고 깨끗한 캐시로 재빌드했다.

## 판정

**PASS** — 첫 플레이에서 발견한 테이블 화살표 충돌을 수정한 뒤 전체 흐름과
이탈 행동을 다시 검증했다. 화면에 보이는 목표와 실제 허용 행동이 일치하며,
대화·화살표가 정보 창·슬라임·주요 조작 버튼을 가리지 않고 첫 주문 정산까지
이어진다.
