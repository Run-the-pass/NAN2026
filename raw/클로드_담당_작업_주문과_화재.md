# 클로드 담당 작업: 주문 시스템과 화재 시스템

## 1. 담당 범위

- 주문 생성 및 표시
- 완성 음식 제출 판정
- 주문 진행도 갱신
- 라운드 종료 시 주문 달성 여부 판정
- 조리 도구의 화재 상태
- 화재 발생 이후 오브젝트 사용 제한
- 인접 오브젝트로의 화재 전파
- 물 슬라임을 이용한 화재 진화
- 주문 및 화재 관련 로그와 시각적 상태 전달

## 2. 작업 원칙

- 기존 슬라임 선택, 이동, 상호작용 조작은 수정하지 않는다.
- 기존 아이템 운반과 조리 작업의 구조를 가능한 한 재사용한다.
- 주문과 화재의 수치 및 대상은 데이터로 변경할 수 있도록 한다.
- 아직 정해지지 않은 규칙을 임의로 확정하지 않는다.
- 미정인 부분은 설정값 또는 별도의 미정 항목으로 남긴다.
- 현재 게임에 존재하지 않는 돈, 수당, 점수 시스템을 추가하지 않는다.

# 주문 시스템

## 3. 주문 데이터

- 주문은 다음 정보를 가진다.
  - 주문 ID
  - 요구 음식 ID
  - 목표 수량
  - 현재 제출 수량

- 주문에 사용되는 음식은 기존 음식 데이터의 ID를 참조한다.
- 음식 이름을 문자열로 직접 비교하지 않는다.
- 한 라운드에 사용할 주문 목록을 외부 데이터에서 전달받을 수 있도록 한다.

## 4. 주문 표시

- 현재 주문의 음식 종류를 표시한다.
- 목표 수량을 표시한다.
- 현재까지 제출한 수량을 표시한다.
- 주문 완료 여부를 표시한다.
- 라운드 제한 시간은 기존 시간 시스템의 값을 사용한다.
- 주문 UI가 게임 로직을 직접 변경하지 않도록 한다.

## 5. 음식 제출

- 슬라임이 완성 음식을 제출대에 운반하면 제출 판정을 수행한다.
- 제출된 음식의 ID를 현재 주문과 비교한다.
- 현재 주문에 포함된 음식이면 해당 주문의 제출 수량을 증가시킨다.
- 목표 수량을 초과해 제출해도 완료 수량은 정상적으로 기록할 수 있다.
- 유효한 제출이 완료되면 제출된 음식은 제거한다.
- 주문 진행도가 변경되면 UI와 로그에 전달한다.

## 6. 잘못된 음식 제출

- 주문에 포함되지 않은 음식은 정상 제출로 처리하지 않는다.
- 잘못된 음식의 처리 방식은 임의로 확정하지 않는다.
- 다음 처리 방식 중 무엇을 사용할지는 별도 설정으로 분리한다.
  - 제출 거부
  - 음식 유지
  - 음식 제거
  - 별도의 실패 처리

## 7. 주문 완료 및 라운드 판정

- 각 주문은 현재 제출 수량이 목표 수량 이상이면 완료 상태가 된다.
- 라운드 종료 시 모든 필수 주문의 완료 여부를 검사한다.
- 목표를 달성하지 못한 경우 게임 오버 판정에 사용할 결과를 반환한다.
- 목표를 달성한 경우 라운드 성공 판정에 사용할 결과를 반환한다.
- 목표를 일찍 달성했을 때 즉시 라운드를 끝낼지는 임의로 결정하지 않는다.
- 라운드의 실제 시작과 종료 처리는 기존 라운드 시스템이 담당한다.

## 8. 주문 시스템에서 제외할 작업

- 새로운 레시피 제작
- 음식 조리 과정 구현
- 슬라임 이동 및 운반 구현
- 제출대 그래픽 제작
- 라운드 정비 단계 구현
- 다음 라운드 주문 미리보기
- 보상 및 돈 시스템
- 주문 실패 패널티 추가

# 화재 시스템

## 9. 화재 대상

- 화재가 발생할 수 있는 조리 도구만 화재 대상이 된다.
- 각 오브젝트는 다음 정보를 가질 수 있다.
  - 화재 발생 가능 여부
  - 현재 화재 상태
  - 화재 전파 가능 여부
  - 인접 오브젝트 정보

- 화재가 발생하지 않는 오브젝트에는 화재 상태를 강제로 추가하지 않는다.
- 바닥 타일은 화재 전파 대상에 포함하지 않는다.

## 10. 화재 발생

- 상호작용을 걸어둔 조리 도구를 방치하면 화재가 발생한다.
- 방치 판정을 시작하는 정확한 시점은 아직 확정되지 않았다.
- 방치 판정 시간도 아직 확정되지 않았다.
- 구현에서는 다음 값을 설정으로 분리한다.
  - 방치 판정 시작 시점
  - 화재 발생까지의 시간
  - 화재 대상 오브젝트 종류

- 방치 조건이 충족되면 해당 오브젝트를 화재 상태로 전환한다.
- 이미 화재 상태인 오브젝트에는 화재 발생 처리를 중복 적용하지 않는다.

## 11. 화재 상태

- 불이 난 오브젝트는 사용할 수 없다.
- 화재 상태에서는 일반 조리 및 상호작용을 시작할 수 없다.
- 화재 상태를 화면에서 명확하게 확인할 수 있어야 한다.
- 화재 상태 진입 시 로그 또는 이벤트를 발생시킨다.
- 화재 상태 해제 전까지 사용 불가 상태를 유지한다.
- 화재로 인한 수당 감소나 돈 차감은 구현하지 않는다.

## 12. 화재 전파

- 화재는 인접한 오브젝트로 옮겨붙을 수 있다.
- 화재는 바닥 타일을 통해 전파되지 않는다.
- 인접 오브젝트 판정은 현재 맵과 오브젝트 배치 정보를 사용한다.
- 화재 전파 간격은 설정값으로 관리한다.
- 다음 대상에는 중복 전파하지 않는다.
  - 이미 불이 난 오브젝트
  - 화재 대상이 아닌 오브젝트
  - 제거되었거나 비활성화된 오브젝트

- 인접 판정의 구체적인 방향과 범위는 기존 맵 구조에 맞춰 분리한다.
- 대각선 인접을 포함할지는 임의로 확정하지 않는다.

## 13. 화재 진화

- 물 슬라임만 화재 진화 작업을 수행할 수 있다.
- 물 슬라임이 불이 난 오브젝트와 5초 동안 상호작용하면 화재가 진압된다.
- 진화 작업 중 진행도를 표시한다.
- 진화가 완료되면 화재 상태를 해제한다.
- 화재가 진압된 오브젝트는 다시 사용할 수 있는 상태가 된다.
- 물 슬라임이 아닌 슬라임이 진화를 시도하면 작업 불가 처리를 한다.
- 진화 중 상호작용이 중단되었을 때 진행도를 유지할지는 임의로 확정하지 않는다.

## 14. 화재 시스템에서 제외할 작업

- 화재로 인한 돈 또는 수당 감소
- 바닥 타일 화재
- 캐릭터에게 불이 옮겨붙는 기능
- 슬라임 체력 감소
- 화재로 인한 슬라임 사망
- 연기 피해
- 소화기 아이템
- 자동 소화 설비
- 화재 보험이나 보상 시스템

# 연동

## 15. 주문 시스템 연동 지점

- 음식 데이터
- 완성 음식 아이템
- 제출대 오브젝트
- 라운드 제한 시간
- 라운드 성공 및 실패 판정
- 주문 UI
- 게임 로그

## 16. 화재 시스템 연동 지점

- 조리 도구 오브젝트
- 오브젝트 상호작용 상태
- 오브젝트 사용 가능 여부
- 맵의 오브젝트 인접 정보
- 슬라임 속성 판정
- 작업 진행도 UI
- 게임 로그

## 17. 완료 조건

### 주문

- 주문 데이터를 받아 현재 주문을 표시할 수 있다.
- 완성 음식이 제출대에 들어오면 주문과 대조할 수 있다.
- 올바른 음식 제출 시 진행도가 증가한다.
- 목표 수량 달성 여부를 판정할 수 있다.
- 라운드 종료 시 성공 또는 실패 결과를 반환할 수 있다.
- 돈과 보상 시스템 없이 동작한다.

### 화재

- 지정된 조리 도구를 화재 상태로 전환할 수 있다.
- 불이 난 오브젝트를 사용할 수 없다.
- 화재가 인접 오브젝트로 전파될 수 있다.
- 화재가 바닥 타일로 번지지 않는다.
- 물 슬라임이 5초 동안 상호작용하면 불을 끌 수 있다.
- 진화 후 오브젝트를 다시 사용할 수 있다.
- 화재로 인한 돈 차감이 발생하지 않는다.

## 18. 미정 사항

- 한 라운드에 동시에 존재하는 주문 수
- 잘못된 음식 제출 시 처리
- 목표 조기 달성 시 라운드 즉시 종료 여부
- 방치 판정이 시작되는 시점
- 화재 발생까지 걸리는 시간
- 화재 전파 간격
- 대각선 방향 화재 전파 여부
- 진화 작업 중단 시 진행도 유지 여부
- 화재 진압 후 오브젝트에 별도 복구 시간이 필요한지 여부
