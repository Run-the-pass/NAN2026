# 펀테스트 전환 이후 변경 사항 정리

## 문서 목적

기존 `AGENTS.md`와 `슬라임 스탯, 요리 가격과 패널티` 문서에 정의된 식당 운영형 MVP를 기준으로, 이후 팀 논의에서 변경되거나 보류된 사항을 정리한다.

현재 목표는 완성형 게임의 전체 구조를 확정하는 것이 아니라, **음성으로 슬라임에게 작업을 지시하는 행위 자체가 재미있는지 빠르게 검증하는 것**이다.

---

## 1. 전체 방향 변화

### 기존 방향

- 음성으로 슬라임에게 명령해 식당을 운영한다.
- 주문 접수, 재료 준비, 조리, 서빙, 판매의 전체 흐름을 구현한다.
- 라운드 사이에 슬라임 합류, 스탯 강화, 복합 명령 해금 등의 보상을 제공한다.
- 슬라임이 성장하면서 단일 행동 명령에서 레시피·팀 단위 명령으로 발전한다.
- 버섯 스튜를 판매하고 매출 목표를 달성하는 방식으로 라운드 성공 여부를 판정한다.

### 현재 방향

- 우선 **3분짜리 단일 펀테스트**로 범위를 축소한다.
- 식당 운영 전반보다 **음성 명령과 작업 타이밍 관리의 재미**를 검증한다.
- 세계관과 제작물은 일반 식당에서 **마탑·슬라임 공방의 마법서 제작** 쪽으로 이동했다.
- 로그라이크, 스쿼드 운영, 장기 성장, 복잡한 업그레이드는 펀테스트 이후로 보류한다.
- 현재 가제는 **`터진다! 슬라임 공방`**이다.

---

## 2. 펀테스트의 핵심 가설

다음 경험이 실제로 재미있는지 확인한다.

> 플레이어가 음성으로 슬라임에게 여러 단계의 작업을 지시하고, 동시에 진행되는 가마솥의 상태와 타이밍을 관리하는 과정이 재미있는가?

이번 테스트에서는 다음을 확인한다.

- 슬라임에게 말로 명령하는 행위가 자연스럽고 즐거운가
- 명령을 내린 뒤 슬라임이 반응하는 모습에서 만족감이 발생하는가
- 두 가마솥의 진행 상태를 보며 다음 명령을 계획하는 것이 재미있는가
- 음성 입력이 마우스 조작의 불편한 대체재가 아니라 고유한 조작 경험으로 느껴지는가
- 실패 원인이 음성인식 오류보다 플레이어의 지휘와 타이밍 실수로 느껴지는가

이번 테스트만으로는 여러 슬라임을 통솔하거나, 명령이 고차원적으로 발전하는 재미까지 검증하지 않는다.

---

## 3. 승리·패배 조건 변경

### 기존

- 라운드 시간: 180초
- 목표 매출: 300G
- 주문을 처리해 판매 수익을 얻는다.
- 제한 시간 초과나 잘못된 서빙에 금전 패널티가 발생한다.

### 변경

- **3분 안에 테스트용 마법서 8장을 만들면 승리한다.**
- 매출, 가격, 고용비, 금전 패널티는 펀테스트에서 사용하지 않는다.
- 10초마다 새로운 주문이 들어오는 시스템은 제거한다.
- 주문 우선순위와 복수 레시피 경쟁도 이번 테스트에서는 다루지 않는다.
- 패배 조건은 기본적으로 제한 시간 안에 목표 수량을 만들지 못하는 것이다.

### 조정 필요

- 8장은 아직 임시 목표 수량이다.
- 이동 시간, 음성 처리 지연, 집기와 투입 시간까지 포함한 실제 플레이 결과를 보고 조정한다.
- 초기 테스트에서 지나치게 어렵다면 5~6장으로 낮춘 뒤 다시 측정한다.

## 4. 레시피 변경

### 기존 버섯 스튜

```text
버섯 가져오기
→ 버섯 손질하기
→ 냄비에 넣기
→ 10초 동안 익히기
→ 그릇에 담기
→ 서빙하기
```

### 현재 테스트용 마법서

```text
1. 가마솥에 초록 약초를 넣는다.
2. 섞는 작업을 실행한다.
3. 5초 동안 기다린다.
4. 양피지를 가마솥에 담근다.
5. 5초 동안 기다린다.
6. 완성된 테스트용 마법서를 꺼낸다.
7. 제출용 테이블에 제출한다.
```

### 추가 후보

- 양피지를 담근 뒤 완성된 마법서를 일정 시간 꺼내지 않으면 녹아 사라지는 기능
- 현재 제안된 유예 시간은 완성 후 5초
- 해당 기능은 긴장감을 만들 수 있지만, 펀테스트 첫 구현 이후로 미뤄도 된다.

## 5. 필요한 오브젝트 변경

### 기존

- 식당 맵
- 버섯 공급대
- 손질대
- 냄비
- 그릇
- 서빙대
- 손님 또는 주문 처리 UI

### 현재 펀테스트

- 제출용 테이블 1개
- 양피지 박스 1개
- 초록 약초 박스 1개
- 가마솥 2개
- 슬라임 1마리

가마솥을 2개 두어 하나의 레시피만으로도 병렬 작업과 타이밍 관리가 발생하도록 한다.

---

## 6. 슬라임 수와 역할 변경

### 기존

- 주방 슬라임과 서빙 슬라임을 구분한다.
- 최대 3마리까지 동시에 활동한다.
- 종류별 스탯과 역할 분담을 활용한다.
- 장기적으로 팀 명령과 스쿼드 운영을 구현한다.

### 현재 펀테스트

- 슬라임은 **1마리만 사용한다.**
- 주방·서빙 역할 구분은 사용하지 않는다.
- 슬라임 종류별 스탯 차이도 우선 검증 대상에서 제외한다.
- 한 마리에게 음성으로 작업을 지시하며 두 가마솥을 번갈아 운영한다.

### 후속 테스트 후보

첫 테스트가 재미있다면 다른 조건은 유지한 채 슬라임만 2마리로 늘려 비교한다.

```text
초록이는 약초를 가져와.
파랑이는 양피지를 가져와.
```

이를 통해 여러 슬라임을 구분해 지휘하는 재미가 실제로 증가하는지 확인한다.

---

## 7. 서빙 시스템 제거

### 기존

- 완성된 요리를 그릇에 담고 서빙대까지 운반한다.
- 서빙은 독립된 작업이며 서빙 역할 슬라임도 존재한다.
- 잘못된 요리 서빙에 별도 패널티가 있다.

### 변경

- 플레이어가 완성품을 손님에게 직접 서빙하는 과정은 제거한다.
- 완성된 마법서를 꺼내 제출용 테이블에 놓는 것까지만 남긴다.
- 향후에는 제출대나 마법진을 통해 자동 납품하는 연출을 사용할 수 있다.
- 별도의 홀, 손님 이동, 테이블 관리, 서빙 동선은 만들지 않는다.

제작에 필요한 운반은 플레이 대상으로 유지하되, 제작이 끝난 뒤의 반복적인 전달 과정은 최소화한다.

---

## 8. 주문 시스템 변경

### 기존

- 주문이 일정 간격으로 계속 들어온다.
- 주문별 제한 시간이 존재한다.
- 주문 성공과 실패가 매출에 반영된다.

### 변경

- 10초마다 주문이 들어오는 시스템을 펀테스트에서 제거한다.
- 레시피가 1개뿐인 상태에서 반복 주문을 넣으면 선택이 아니라 동일 작업의 재촉만 발생한다고 판단했다.
- 이번 테스트에서는 `마법서 8장 제작`이라는 단일 생산 목표만 제공한다.
- 복수 주문, 긴급 주문, 주문 우선순위는 레시피가 2개 이상일 때 다시 검토한다.

---

## 9. 업그레이드와 성장 시스템 보류

### 기존

- 라운드 사이에 다음 선택지를 제공한다.
 - 새로운 슬라임 합류
 - 개별 스탯 강화
 - 전체 스탯 강화
 - 복합 명령 해금
 - 팀 명령 해금
 - 일시적인 라운드 효과

### 현재

- 펀테스트에는 업그레이드와 보상 선택을 넣지 않는다.
- 작업 속도, 이동 속도, 청력, 집중력의 성장도 우선 적용하지 않는다.
- 명령의 추상화와 스쿼드 명령은 장기 방향으로 유지할 수 있으나, 현재 구현 범위에서는 제외한다.

### 보류 이유

- 업그레이드를 넣으려면 여러 라운드와 보상 화면이 필요하다.
- 스쿼드 명령을 유의미하게 만들려면 다단계 생산, 다수 슬라임, 넓은 맵이 필요하다.
- 남은 개발 기간에 이를 모두 구현하면 핵심 재미를 확인하기 전에 범위가 폭발할 가능성이 높다.

---

## 10. 명령 추상화와 공장형 구조의 위치

### 논의된 장기 방향

초반에는 개별 행동을 지시하고, 성장 이후에는 더 큰 작업 단위를 명령한다.

```text
초반
"약초 가져와."
"가마솥에 넣어."
"양피지를 담가."

후반
"회복 마법서 만들어."
"제작조는 방어 주문서를 생산해."
```

이 구조가 필수 시스템이 되려면 다음과 같은 생산 위계가 필요하다.

```text
원재료 A
→ 중간재 B
→ 완성품 C
```

예를 들어 약초로 원액을 만들고, 원액으로 물약을 만들고, 물약으로 주문서를 만드는 식이다.

### 현재 판단

- 해당 방향은 음성 명령의 성장과 잘 맞는다.
- 하지만 다단계 공정, 스쿼드, 맵 확장까지 붙으면 유사 공장 게임 규모가 된다.
- 따라서 지금은 구현하지 않고, 기본 음성 조작의 재미가 확인된 뒤 후속 설계로 판단한다.

## 11. 맵 방향 변화

### 기존 논의

- 3라운드마다 새로운 맵으로 이동
- 약 5개 맵을 순서대로 플레이
- 장애물과 작업대 배치를 바꾸어 변화를 제공

### 추가로 나온 방향

음성 명령과 생산 공정이 확장된다면 맵을 완전히 교체하기보다, 기존 작업장에 시설과 공간이 추가되는 증축형 구조가 자연스러울 수 있다는 의견이 나왔다.

```text
기본 공방
→ 추출 구역 추가
→ 연성 구역 추가
→ 주문 각인 구역 추가
```

### 현재 상태

- 맵 5개 교체와 증축형 맵 중 어느 쪽도 확정하지 않는다.
- 펀테스트에서는 최소한의 고정 맵 하나만 사용한다.
- 이후 음성 조작의 재미와 필요한 작업량을 보고 결정한다.

## 12. 세계관과 명칭 변화

### 기존

- 일반적인 슬라임 식당
- 버섯 스튜 조리와 판매
- 주방과 서빙 역할

### 현재

- 마탑 또는 마법 공방 분위기
- 슬라임은 마법사의 사역마 또는 공방 일꾼
- 초록 약초와 양피지로 마법서를 제작
- 완성품은 제출대 또는 마법진을 통해 납품
- 가제: `터진다! 슬라임 공방`

마탑·공방 콘셉트는 음성 명령을 주문이나 사역마 지휘로 자연스럽게 설명할 수 있다는 장점이 있다.

## 14. 현재 구현 우선순위

### 즉시 구현

1. 고정된 펀테스트 맵
2. 슬라임 1마리
3. 음성 명령으로 이동 및 물건 운반
4. 초록 약초와 양피지 상호작용
5. 가마솥 2개의 상태 전이
6. 5초 섞기와 5초 각인
7. 완성된 마법서 회수와 제출
8. 3분 제한과 목표 수량 판정
9. 명령 인식 결과와 작업 상태 피드백
10. 실제 플레이를 통한 재미 검증

### 펀테스트 이후 판단

- 슬라임 2마리 비교 테스트
- 레시피 2종
- 반복 주문과 주문 우선순위
- 명령 업그레이드
- 슬라임 스탯과 종류
- 스쿼드 및 팀 명령
- 여러 맵 또는 공방 증축
- 점수, 매출, 가격, 금전 패널티
- 장기 성장 구조

## 15. 현재 상태 한 문장 요약

> 식당에서 여러 슬라임을 성장시키며 주문과 서빙을 처리하는 게임에서, 마법 공방에서 슬라임 한 마리에게 음성으로 다단계 작업을 지시하고 두 가마솥의 타이밍을 관리해 3분 안에 마법서 8장을 만드는 펀테스트로 범위를 축소했다.

## 16. 기존 문서에서 우선 수정할 항목

### `AGENTS.md`

- 프로젝트 개요의 `식당 운영`을 현재 펀테스트용 `마법 공방 운영`으로 임시 변경
- 게임 흐름에서 선택, 성장, 다음 라운드를 펀테스트 범위 밖으로 이동
- 식당 운영 단계의 주문 접수, 서빙, 판매 제거
- 해커톤 구현 범위를 펀테스트 오브젝트와 승리 조건에 맞게 축소
- 제작 순서에서 주문·서빙과 강화 단계를 뒤로 이동
- 명령 추상화는 장기 방향으로 표시하고 현재 테스트 범위와 분리

### `슬라임 스탯, 요리 가격과 패널티.md`
