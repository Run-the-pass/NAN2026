# 슬라임 레스토랑 튜토리얼 구현 명세

## 1. 목적
이 문서는 **아르바이트 모드 1스테이지의 초반 튜토리얼을 실제 플레이 행동 중심으로 구성하기 위한 구현 명세**다.
기존처럼 여러 시스템과 슬라임을 대사로 한꺼번에 설명하지 않는다.
핵심 원칙은 다음과 같다.
> **짧게 설명 → 직접 행동 → 필요한 순간에 다음 설명 → 다시 행동**
플레이어가 아직 경험하지 않은 시스템을 미리 장문으로 설명하지 않는다. 
1스테이지 초반에 기본 조작과 게임 구조를 직접 익힌 뒤, 이후 시스템과 2·3스테이지의 신규 요소는 필요한 시점에 짧은 다이얼로그로만 안내한다.

## 2. 튜토리얼에서 반드시 가르칠 것
1스테이지 초반 튜토리얼의 최우선 학습 목표는 아래 순서다.
1. 슬라임 선택
2. 이동
3. 재료 집기
4. 작업대와 상호작용
5. 행동력(AP)
6. 턴 종료
7. 완성된 음식의 이동 및 전달
8. 그릇에 담기
9. 주문 제출
아래 항목은 한꺼번에 설명하지 않는다.
- 다음 주문 미리보기
- 다른 슬라임의 모든 세부 역할
- 설거지의 전체 규칙
- 편의 단축키
- 2·3스테이지에서 처음 등장하는 조리 도구
이들은 실제로 필요해지는 순간에 짧게 안내한다.

## 3. 전체 구성 원칙
### 3.1 설명보다 행동을 먼저 연결한다
잘못된 예:
> 턴 설명 → 행동력 설명 → 주문표 설명 → 슬라임 4종 설명 → 그릇 설명 → 설거지 설명 → 플레이 시작
권장 구조:
> 한 문장 설명 → 행동 1~2회 → 짧은 추가 설명 → 행동 → 다음 시스템 공개

### 3.2 처음부터 네 슬라임을 전부 보여주지 않는다
튜토리얼 시작 시에는 **땅 슬라임만 활성화/노출**한다.
다른 슬라임은 튜토리얼 진행에 따라 필요한 순간에 등장시킨다.
첫 과제는 **썰은 양배추 주문**으로 고정한다.
땅 슬라임은 이 과정에서 다음 행동을 담당한다.

- 이동
- 양배추 집기
- 도마 사용
- 썰은 양배추 완성

### 3.3 물 슬라임은 음식 완성 이후 등장시킨다
땅 슬라임이 양배추를 다 썬 뒤 물 슬라임을 등장시킨다.
목적은 다음과 같다.
- 처음부터 여러 슬라임을 동시에 보여줘 정보량이 늘어나는 것을 방지
- 작업이 완료된 뒤 새로운 역할을 하나씩 소개
- 테이블을 이용한 음식/그릇 전달을 자연스럽게 학습
- 이후 제출과 그릇 시스템으로 연결

정확한 이동 칸 수와 테이블 위치는 현재 1스테이지 맵 구조에 맞추되, **땅 슬라임과 물 슬라임 사이에 테이블을 통한 전달이 자연스럽게 발생하도록 배치**한다.

## 4. 1스테이지 튜토리얼 상세 흐름
### Phase 0. 시작

#### 상태
- 땅 슬라임만 등장
- 다른 슬라임은 숨김 또는 비활성화
- 첫 주문: `썰은 양배추`
- 플레이어가 사용할 수 없는 기능은 가능하면 UI에서도 잠시 숨기거나 비활성 표시

### Phase 1. 슬라임 선택과 이동
#### 목표
플레이어가 땅 슬라임을 선택하고 양배추 쪽으로 이동한다.

#### 트리거
- 최초 슬라임 선택
- 최초 이동

#### 안내
첫 선택 전:
> "먼저 이 친구를 선택해보세요."

선택 후:
> "이동할 수 있는 칸이 표시돼요. 양배추 쪽으로 가볼까요?"

#### 구현 규칙
- 플레이어가 다른 위치를 선택해도 게임이 망가지지 않는 범위라면 허용
- 튜토리얼 목표와 무관한 상호작용은 기존 규칙대로 실패 처리
- 필요한 경우 목표 오브젝트에 화살표/하이라이트 표시

### Phase 2. 재료 집기
#### 목표
땅 슬라임이 양배추를 집는다.

#### 트리거

- 양배추 재료 공급대와 최초 상호작용

#### 안내
> "좋아요. 재료나 도구 앞에서는 상호작용해서 일을 시킬 수 있어요."
이 시점에는 아직 도마 사용법까지 장문으로 설명하지 않는다.

### Phase 3. 행동력(AP)과 턴 종료
#### 목표
플레이어가 행동 횟수에 제한이 있다는 것을 첫 행동 경험 뒤 이해한다.

#### 트리거
- 최초 이동 또는 최초 상호작용으로 AP가 실제 감소한 직후

#### 안내
> "슬라임은 한 턴에 행동할 수 있는 횟수가 정해져 있어요." 
> "남은 행동력은 슬라임 UI에서 확인할 수 있어요."

AP를 모두 사용했거나 더 행동할 필요가 없는 시점:
> "행동을 마쳤다면 턴을 넘겨주세요."

#### 구현 규칙
- 설명은 AP가 실제로 감소한 뒤 보여준다.
- UI에서 현재 AP 감소가 시각적으로 확인되어야 한다.
- 턴 종료 버튼을 최초 1회 강조한다.
- `Space` 등의 단축키는 실제 조작으로 확정되어 있을 때만 보조 안내로 제공한다.
- 단축키가 아직 확정되지 않았거나 구현되지 않았다면 튜토리얼에서 언급하지 않는다.

### Phase 4. 도마 사용
#### 목표
양배추를 도마로 가져가 썬다.

#### 트리거
- 양배추를 든 땅 슬라임이 도마와 상호작용
- 또는 현재 구현 규칙에 따라 도마 작업 시작

#### 안내
> "이 친구는 재료 손질을 잘해요. 양배추를 도마에서 썰어볼까요?"

#### 구현 규칙
- 도마는 땅 슬라임의 역할을 자연스럽게 보여주는 첫 전용 도구로 사용한다.
- 처음부터 "땅 슬라임은 무엇을 할 수 있고 무엇을 못 한다"는 목록을 설명하지 않는다.
- 실제 행동을 한 뒤 역할을 이해하게 한다.

### Phase 5. 썰은 양배추 완성 → 물 슬라임 등장
#### 트리거
`썰은 양배추`가 완성된 순간.

#### 상태 변화

- 물 슬라임 등장/활성화
- 필요하다면 짧은 등장 연출
- 테이블을 이용한 전달 동선을 하이라이트

#### 안내
> "잘했어요! 그런데 완성한 음식은 그릇에 담아 손님에게 보내야 해요." 
> "이번에는 퐁당이가 도와줄 거예요."

물 슬라임 소개는 1~2문장으로 끝낸다.
※ 물 슬라임의 설거지/음료 역할을 이 시점에 전부 설명하지 않는다.

### Phase 6. 테이블을 이용한 전달
#### 목표
두 슬라임이 테이블을 이용해 완성된 음식과 그릇을 연결하고 제출 가능한 상태로 만든다.

#### 설계 원칙
정확한 세부 순서는 현재 테이블/그릇 구현 규칙을 따른다.
현재 기준으로 가능한 상호작용 예시는 다음과 같다.

- 음식 + 테이블 위 그릇 → 음식이 그릇에 들어감
- 그릇 + 테이블 위 음식 → 음식이 그릇에 들어감
- 빈손 + 완성된 음식이 담긴 그릇 → 그릇을 집음

#### 안내
플레이어가 처음 테이블을 사용할 때만 짧게 설명한다.
> "테이블에 음식이나 그릇을 올려두면 다른 슬라임에게 넘겨줄 수 있어요."
그릇에 음식이 들어가는 순간:
> "음식은 그릇에 담아야 제출할 수 있어요."

#### 구현 규칙
- 튜토리얼 전용 스크립트가 실제 테이블 규칙을 우회하지 않는다.
- 실제 게임에서도 사용하는 상호작용 규칙 그대로 학습하게 한다.
- 특정 칸에 정확히 서야만 성공하는 식의 과도한 강제는 피한다.

### Phase 7. 주문 제출
#### 목표
플레이어가 완성된 `썰은 양배추`를 제출한다.

#### 트리거
- 현재 주문과 일치하는 음식 제출 성공

#### 안내
> "완성된 음식은 제출대에 가져가면 주문을 완료할 수 있어요."

성공 후:
> "좋아요! 첫 주문 완료예요."

#### 잘못된 음식 제출
현재 주문과 일치하지 않는 음식은 제출되지 않는다.

- 음식 유지
- AP 미소모
- 짧은 실패 피드백
- 예: `현재 주문에 없는 음식입니다.`

튜토리얼에서도 같은 규칙을 사용한다.

### Phase 8. 그릇 / 설거지
설거지는 **1차 튜토리얼의 핵심 학습 목표보다 우선순위가 낮다.**
현재 구현 및 시간 상황에 따라 아래 둘 중 하나를 선택한다.

#### A안. 직접 체험
주문 제출 한 턴 뒤 더러운 그릇이 생성되는 현재 규칙을 유지한다면:

1. 더러운 그릇 생성
2. 물 슬라임 강조
3. 설거지대 강조
4. 직접 한 번 씻게 함

안내:
> "서빙한 뒤에는 더러운 그릇이 돌아와요." 
> "퐁당이는 이런 물을 쓰는 일을 잘해요."

#### B안. 짧은 안내만 제공
튜토리얼이 너무 길어지거나 구현 시간이 부족하면 직접 강제하지 않는다.
> "서빙한 그릇은 나중에 더러운 상태로 돌아와요. 그때 퐁당이에게 설거지를 맡겨주세요."
이후 실제 플레이에서 첫 더러운 그릇이 발생했을 때 짧은 팝업을 한 번 더 띄운다.

#### 권장
마감 상황에서는 **B안 우선**.

### Phase 9. 다른 슬라임 소개
첫 주문이 완료된 뒤 나머지 슬라임을 등장시킨다.

#### 원칙
각 슬라임을 장문으로 설명하지 않는다.
1~2문장으로 캐릭터성과 핵심 역할만 소개한다.
예시:
- 불 슬라임: 불을 사용하는 조리 담당
- 전기 슬라임: 다른 슬라임보다 한 턴에 더 많이 행동하며 전기 도구 담당
- 땅 슬라임: 재료 손질 담당
- 물 슬라임: 물을 사용하는 작업 담당
전기 슬라임은 단순히 "두 배 빠르다"라고 설명하지 않는다.

현재 시스템상 핵심 차이는 **AP 2**이므로 다음처럼 설명한다.
> "번쩍이는 다른 친구들보다 한 턴에 한 번 더 행동할 수 있어요."

### Phase 10. 튜토리얼 종료
마지막 안내:
> "슬라임을 선택하면 UI에서 이 친구가 할 수 있는 행동과 남은 행동력을 확인할 수 있어요." 
> "이제 다음 주문부터는 직접 처리해보세요!"
이후부터는 일반 1스테이지 플레이로 전환한다.
튜토리얼 전용 강제 이동/하이라이트/잠금은 해제한다.

## 5. 다음 주문 미리보기 안내
`다음 주문` 시스템은 튜토리얼 초반에 설명하지 않는다.
첫 주문 완료 이후 또는 실제로 플레이어가 다음 주문을 고려할 수 있는 시점에 한 번만 안내한다.
예시:
> "옆에 작게 보이는 주문은 다음에 들어올 주문이에요." 
> "미리 준비해두면 턴을 아낄 수 있겠죠?"
다음 주문은 **미리 만들어둘 수는 있지만 활성 주문이 되기 전에는 제출할 수 없다.**

## 6. 2·3스테이지 튜토리얼
2스테이지와 3스테이지에서는 1스테이지와 같은 강제형 튜토리얼을 반복하지 않는다.

### 원칙
- 신규 요소가 처음 등장할 때만 짧은 다이얼로그
- 이미 배운 이동/AP/턴 종료/제출을 다시 설명하지 않음
- 새로운 조리기구나 슬라임 역할만 설명
- 설명 직후 실제 플레이로 넘김
- 대사만으로 충분한 내용은 별도 강제 튜토리얼을 만들지 않음

이후 플레이어가 직접 진행한다.

## 7. 튜토리얼 UI
튜토리얼 안내는 가능한 한 아래 방식으로 구현한다.

### 우선순위
1. 대상 오브젝트 하이라이트
2. 짧은 화살표
3. 점장 슬라임 짧은 대사
4. 필요한 경우에만 입력 잠금

### 피해야 할 것
- 화면 대부분을 가리는 장문 팝업
- 한 팝업에서 여러 규칙 설명
- 아직 사용할 수 없는 시스템 설명
- 매 행동마다 강제로 대사를 띄우는 것
- 이미 이해한 행동을 반복 강제하는 것

## 8. 튜토리얼 상태 관리
튜토리얼은 명시적인 단계 상태를 가진다.

예시:
```text
INTRO
SELECT_EARTH
MOVE_TO_CABBAGE
PICK_CABBAGE
EXPLAIN_AP
END_TURN_FIRST
USE_CUTTING_BOARD
FOOD_COMPLETE
REVEAL_WATER
USE_TABLE
PLATE_FOOD
SUBMIT_ORDER
DISH_GUIDE_OPTIONAL
REVEAL_OTHER_SLIMES
TUTORIAL_COMPLETE
```

각 단계는 **행동 성공 이벤트**를 기준으로 다음 단계로 넘어간다.
시간 경과만으로 단계를 넘기지 않는다.

## 9. 실패 및 예외 처리
튜토리얼 중 플레이어가 예상과 다른 행동을 해도 가능한 한 게임을 막지 않는다.

### 공통 규칙
- 잘못된 상호작용은 AP 미소모
- 목표와 다른 곳으로 이동했다고 즉시 리셋하지 않음
- 일정 시간 또는 일정 턴 동안 진행이 없을 때만 힌트 재표시
- 플레이어가 이미 필요한 행동을 수행했다면 해당 튜토리얼 단계를 자동 완료
- 튜토리얼 때문에 실제 게임 규칙과 다른 예외 규칙을 만들지 않음

### 소프트락 방지
각 단계 진입 시 다음을 확인한다.
- 필요한 재료가 존재하는가
- 필요한 슬라임이 활성화되어 있는가
- 목표 오브젝트까지 이동 가능한가
- 음식/그릇이 잘못된 상태로 잠기지 않았는가
- 튜토리얼 진행 이벤트를 이미 놓친 상태가 아닌가

소프트락이 발생 가능한 경우에는 현재 단계의 시작 상태로 복구할 수 있는 안전장치를 둔다.

## 10. 대사 작성 기준
### 권장

- 한 대사창 1~2문장
- 한 번에 하나의 개념만 설명
- 설명 직후 바로 행동
- 캐릭터성은 시스템 설명을 방해하지 않는 범위에서 사용
- 플레이어가 이미 화면에서 볼 수 있는 내용을 장황하게 반복하지 않음

### 비권장
> "오른쪽 위에 시계 보이시죠? 저건 오늘 하루동안 일할 수 있는 턴이에요! 턴이 뭐냐고요? 간단하게 말씀드리자면..."

처럼 한 시스템을 여러 문장으로 길게 정의하는 방식.

권장:
> "오른쪽 위 숫자가 남은 턴이에요. 턴을 넘길 때마다 하나씩 줄어들어요."

그리고 바로 플레이를 이어간다.

## 11. 구현 우선순위
시간이 부족하면 아래 순서대로 구현한다.

### P0 — 반드시 구현
- 땅 슬라임만으로 시작
- 썰은 양배추 첫 주문
- 이동/재료 집기/도마 상호작용
- AP 안내
- 턴 종료 안내
- 음식 완성 후 물 슬라임 등장
- 그릇 및 제출 안내
- 첫 주문 완료 후 일반 플레이 전환

### P1 — 가능하면 구현
- 테이블 전달 하이라이트
- 나머지 슬라임 순차 소개
- 다음 주문 미리보기 안내
- 힌트 재표시

### P2 — 시간 여유가 있을 때
- 설거지 직접 체험
- 세부 연출
- 단축키 안내
- 고급 애니메이션/카메라 연출

## 12. 완료 조건
다음 조건을 만족하면 1스테이지 튜토리얼 구현 완료로 본다.
- 플레이어가 장문의 사전 설명 없이 직접 첫 주문을 완수할 수 있음
- 첫 주문 과정에서 이동, 상호작용, AP, 턴 종료, 그릇, 제출을 실제로 한 번 이상 경험함
- 다른 슬라임은 필요한 순간 이전에 과도하게 설명되지 않음
- 튜토리얼 종료 후 일반 게임 규칙과 조작 방식이 그대로 이어짐
- 튜토리얼 때문에 별도의 예외 규칙이 과도하게 추가되지 않음
- 튜토리얼을 처음 보는 사람이 외부 설명 없이 진행 가능한지 플레이테스트로 확인함

## 13. 핵심 요약
튜토리얼의 목적은 게임의 모든 규칙을 설명하는 것이 아니다.
**첫 주문 하나를 직접 해결하게 하면서 게임을 플레이하는 법을 이해시키는 것**이 목적이다.
따라서 1스테이지 초반은 아래 흐름을 기준으로 구현한다.

```text
짧은 시작 대사
→ 땅 슬라임 선택
→ 이동
→ 양배추 집기
→ AP/턴 종료 학습
→ 도마에서 양배추 썰기
→ 음식 완성
→ 물 슬라임 등장
→ 테이블/그릇을 이용한 전달
→ 주문 제출
→ 나머지 슬라임 짧게 소개
→ 일반 플레이 전환
```

2·3스테이지에서는 이 구조를 반복하지 않고, **새로운 요소가 실제로 등장하는 순간 짧은 다이얼로그만 제공한다.**
