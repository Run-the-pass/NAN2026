# NAN 2026 프로젝트 브리프

## 프로젝트 개요

- NAN 2026 해커톤을 위한 Phaser 3 기반 웹 게임이다.
- 플레이어는 음성으로 슬라임에게 명령해 식당을 운영한다.
- 슬라임은 완벽한 작업자가 아니며, 플레이어는 각 슬라임의 성격과 숙련도를 파악하고 적절하게 지시해야 한다.
- 초반에는 행동을 하나씩 명령하지만, 성장하면 여러 작업을 묶은 추상적인 명령을 사용할 수 있다.

```text
초반
"말랑아 버섯 가져와."
"말랑아 버섯 손질해."
"빨강아 냄비에 넣어."

성장 이후
"말랑아 재료 준비해."
"주방팀 버섯 스튜 만들어."
```

핵심 성장 경험은 슬라임의 능력치 상승, 슬라임 수의 향상, 명령의 추상화에 있다.

## 핵심 경험

플레이어는 다음 과정을 반복한다.

1. 음성으로 슬라임에게 명령한다.
2. 슬라임이 명령을 이해하고 행동한다.
3. 슬라임의 성격이나 숙련도 때문에 예상 가능한 문제가 발생한다.
4. 플레이어가 상황을 파악하고 다시 지시한다.
5. 성장한 슬라임에게 더 짧고 추상적인 명령을 내린다.

슬라임의 불완전함은 순수한 무작위 오류로 만들지 않는다.

좋은 예:

- 배고픈 슬라임이 버섯을 먹으려 한다.
- 숙련도가 낮아 손질이 느리다.
- 한 번에 기억할 수 있는 명령 수가 부족하다.

나쁜 예:

- 이유 없이 명령을 무시한다.
- 정확히 전달된 명령을 무작위로 바꾼다.

플레이어가 사고의 원인을 이해하고 대응할 수 있어야 한다.

## 게임 흐름

```text
게임 시작
→ 슬라임 또는 강화 선택
→ 식당 운영
→ 목표 달성 판정
→ 성장 또는 정비
→ 다음 라운드
```

### 선택

라운드 사이 선택지는 다음 중 하나다.

- 새로운 슬라임 합류
- 기존 슬라임 강화
- 새로운 명령 해금
- 전체 슬라임 강화
- 다음 라운드에만 적용되는 효과

### 식당 운영

제한 시간 동안 다음 작업을 수행한다.

1. 주문 접수
2. 재료 준비
3. 조리
4. 서빙
5. 판매

플레이어는 직접 이동하면서 음성으로 슬라임에게 명령한다.

### 성장

- 이동 및 작업 속도 증가
- 들을 수 있는 범위 증가
- 기억할 수 있는 명령 수 증가
- 복합 작업 수행
- 다른 슬라임과 역할 분담
- 팀 단위 명령 수행

## 명령 단계

### 1단계: 단일 행동

`"말랑아 버섯 가져와."` → `GET(mushroom)`

### 2단계: 연속 명령

`"말랑아 버섯 가져와서 손질해."`

```text
GET(mushroom)
→ MOVE(cutting-board)
→ CHOP(mushroom)
```

### 3단계: 작업 명령

`"말랑아 재료 준비해."`

슬라임이 필요한 재료를 가져와 손질한다.

### 4단계: 레시피 명령

`"빨강아 버섯 스튜 만들어."`

슬라임이 레시피에 포함된 작업을 순서대로 수행한다.

### 5단계: 팀 명령

`"주방팀 버섯 스튜 만들어."`

여러 슬라임이 재료 준비, 조리, 정리를 분담한다.

## 음성 명령 파이프라인

```text
마이크 입력
→ 오디오 녹음
→ Gemini 명령 해석
→ 명령 JSON
→ 게임 상태를 기준으로 검증
→ 세부 작업으로 분해
→ Phaser에서 슬라임 행동 실행
```

- 실시간 자막은 디버깅 참고 정보이며 게임 명령의 입력으로 사용하지 않는다.
- Gemini는 사용자의 의도를 구조화한다.
- 실제 작업 순서와 행동 결과는 게임 코드가 결정한다.

```json
{
  "status": "OK",
  "confidence": 0.94,
  "commands": [
    {
      "actorId": "slime-01",
      "action": "GET",
      "targetId": "mushroom-box",
      "destinationId": null,
      "sequence": 1
    }
  ],
  "reason": null
}
```

슬라임, 행동, 대상은 현재 게임에 존재하는 후보 중에서만 선택한다. AI가 새로운 이름이나 행동을 만들지 않도록 제한한다.

## 해커톤 구현 범위

최소 시연 버전:

- Phaser 3 기반 웹 게임
- 고정된 식당 맵
- 주방과 서빙 슬라임
- 레시피 1개
- 주문 1종
- 음성에서 명령 JSON 생성
- 단일 행동 명령
- 복합 명령 또는 팀 명령 1종
- 슬라임의 관찰 가능한 실수 1종
- 강화 전후의 명령 방식 변화
- 짧은 라운드의 시작과 종료

초기 범위에서 제외:

- 대규모 스킬트리
- 다수의 맵과 레시피
- 복잡한 장기 육성
- 온라인 멀티플레이
- 완전한 자율 AI
- 많은 종류의 전설 능력
- 장기 달력 시스템

## 기술 구성

- 게임 엔진: Phaser 3
- 언어: TypeScript
- 실행 환경: 데스크톱 웹 브라우저
- 음성 명령 해석: Gemini API
- 배포 및 백엔드: Firebase
- 프로젝트 지식 관리: LLM Wiki
- 구현 원칙: Ponytail

현재 시연에 필요한 최소 구현을 우선한다. 기존 코드, 브라우저 기능, Phaser 기능으로 해결할 수 있다면 새로운 시스템이나 의존성을 추가하지 않는다.

## 개발 파이프라인

```text
계획
→ 작업
→ 검증
```

### 계획 에이전트

- wiki에서 관련 기획을 확인한다.
- 이번에 구현할 기능의 범위를 정한다.
- 구현하지 않을 범위를 명시한다.
- 검증 가능한 완료 조건을 작성한다.
- 코드는 수정하지 않는다.

### 작업 에이전트

- 계획된 범위만 구현한다.
- Ponytail 원칙에 따라 가장 작은 구현을 선택한다.
- 완료 조건과 무관한 기능이나 구조를 추가하지 않는다.
- 구현 결과와 남은 문제를 보고한다.

### 검증 에이전트

- 완료 조건을 기준으로 실제 동작을 확인한다.
- 빌드, 게임 플레이, 오류와 회귀를 검사한다.
- 직접 기능을 확장하지 않는다.
- `PASS`, `FIX`, `REPLAN` 중 하나로 판정한다.
- 같은 문제가 반복되면 무한히 수정하지 않고 사용자에게 판단을 요청한다.

## 제작 순서

1. Phaser 기본 맵과 슬라임
2. 명령 JSON으로 슬라임 이동
3. 재료 가져오기와 손질
4. 오디오에서 명령 JSON 생성
5. 조리와 요리 완성
6. 주문과 서빙
7. 복합 명령
8. 강화 전후의 명령 변화
9. 라운드 진행
10. Firebase 배포와 시연 안정화

각 단계는 독립적으로 실행하고 검증할 수 있어야 한다.

- 밸런싱과 자동 검증을 위해 게임 로직은 그래픽 렌더링과 분리한다.
- 그래픽 없이 게임 상태와 명령을 입력하고 행동, 작업 결과, 점수, 소요 시간을 출력할 수 있어야 한다.
- 동일한 입력과 랜덤 시드를 사용하면 동일한 결과를 재현할 수 있어야 한다.
