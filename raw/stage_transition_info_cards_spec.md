# 스테이지 전환 정보 화면 UI 구현 명세

## 1. 목적

이 문서는 스테이지와 스테이지 사이에 표시하는 정보 화면만 정의한다.

화면은 사용자가 제공한 `image(132).png`의 구성을 기준으로 구현한다.

핵심 목적은 플레이어가 다음 스테이지에 들어가기 전에 다음 정보를 한 화면에서 확인하게 하는 것이다.

- 스테이지 번호와 이름
- 다음 스테이지의 맵 배치
- 나올 수 있는 음식 목록
- 음식별 재료와 제작 도구
- 스테이지 TIP
- 다음 단계로 이동하는 버튼

## 2. 범위

### 2.1 포함

- 스테이지 정보 화면
- 맵 미리보기
- 최대 6개의 음식 목록
- 음식 아이콘 호버 시 재료와 제작 아이콘 표시
- TIP 최대 2개
- 다음 버튼
- 다음 버튼 이후 슬라임 영입 화면 또는 인게임으로 연결
- 화면 데이터와 실제 게임 데이터 연결
- 단위, 통합, 시각 테스트

### 2.2 제외

- 별도의 도구 정보 카드
- 인게임 중 상세 인포 팝업
- 점수와 랭킹
- 새로운 레시피나 게임 규칙 추가
- 로딩 시간이 없는데도 표시하는 가짜 로딩 화면

슬라임 영입 화면은 이 문서에서 디자인하지 않는다. 다음 버튼이 영입 화면으로 이동해야 하는 경우의 연결 지점만 다룬다.

## 3. 현재 구현 기준

현재 코드 기준선은 `design-doc.md`의 2026-08-02, 커밋 `9dd34de` 보고 내용으로 한다.

화면에 표시할 수 있는 현재 게임 데이터는 다음과 같다.

- 스테이지: `id`, `name`, `orders`, `timeLimitMs`
- 현재 음식: 버섯, 버섯 구이
- 현재 설비: 재료 상자, 조리 도구, 그릇 생성대, 세척기, 테이블, 제출대, 쓰레기 처리
- 현재 맵: 16×10 타일

다음 항목은 이 화면에서 되살리지 않는다.

- 음성 명령
- 약초, 물약, 스크롤
- 슬라임 죽음
- 바닥 타일 화재
- 주문별 1분 제한과 20초 단위 색상 변화

## 4. 화면 흐름

### 4.1 스테이지 클리어 후

```text
인게임 종료
→ 스테이지 결과
→ 다음 스테이지 정보 화면
→ 다음 버튼
→ 슬라임 영입이 있으면 영입 화면
→ 실제 로딩이 필요하면 로딩
→ 다음 인게임
```

### 4.2 첫 스테이지 시작 전

현재 첫 진입 흐름에 초기 슬라임 선택이 존재한다. 실제 화면 순서는 기존 상태 관리 구조를 확인한 뒤 연결하되, 첫 인게임 전에 스테이지 정보 화면이 한 번 표시되어야 한다.

```text
타이틀
→ 기존 초기 슬라임 선택
→ 첫 스테이지 정보 화면
→ 인게임
```

기존 코드의 실제 순서가 다르면 초기 슬라임 선택을 새로 복제하지 말고 기존 흐름에 정보 화면만 삽입한다.

### 4.3 화면이 열린 동안

- 게임 타이머는 진행되지 않는다.
- 슬라임, 설비, 주문, 화재 상태는 갱신되지 않는다.
- 맵 미리보기는 실제 플레이 중인 월드가 아니다.
- 배경 클릭으로 화면이 닫히지 않는다.
- 다음 버튼을 눌러야 다음 상태로 이동한다.

## 5. 레퍼런스 화면 구조

제공된 그림의 정보 계층과 배치 비율을 따른다.

```text
┌──────────────────────────────────────────────────────────────┐
│ 3-3 : 스테이지 이름                                          │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌────────────────────────────┐  ┌────────────────────────┐  │
│  │                            │  │ 나올 수 있는 음식 목록 │  │
│  │                            │  │                        │  │
│  │       맵 미리보기          │  │   ○     ○     ○       │  │
│  │                            │  │                        │  │
│  │                            │  │   ○     ○     ○       │  │
│  └────────────────────────────┘  └────────────────────────┘  │
│                                                              │
│                 TIP: 첫 번째 안내                            │
│                 TIP: 두 번째 안내                            │
│                                                              │
│                            [ 다음 ]                           │
└──────────────────────────────────────────────────────────────┘
```

### 5.1 반드시 유지할 구조

- 상단 제목 영역을 본문과 분리한다.
- 본문 좌측에 맵 미리보기를 둔다.
- 본문 우측에 음식 목록 패널을 둔다.
- 음식 목록은 3열×2행, 최대 6칸으로 구성한다.
- TIP은 맵 아래쪽에 최대 2개를 배치한다.
- 다음 버튼은 화면 하단 중앙에 배치한다.

### 5.2 그대로 복제하지 않아도 되는 것

- 목업의 파란 배경과 빨간 버튼은 최종 색상 확정안이 아니다.
- 목업의 원형 파란 자리표시자는 실제 음식 아이콘으로 교체한다.
- 목업의 임시 글꼴과 정확한 픽셀값을 복사할 필요는 없다.
- 최종 화면은 기존 게임의 버튼, 외곽선, 흰색 패딩 스타일에 맞춘다.

## 6. 기준 해상도와 영역 비율

기준 논리 해상도는 1280×720, 화면 비율은 16:9로 한다.

절대 좌표를 그대로 박지 말고 기준 해상도에 대한 비율과 안전 여백을 사용한다.

### 6.1 권장 영역

| 영역 | 권장 비율 |
|---|---:|
| 화면 바깥 안전 여백 | 좌우 각각 3~4% |
| 상단 제목 영역 | 화면 높이의 13~15% |
| 제목과 본문 사이 간격 | 화면 높이의 2~3% |
| 본문 영역 | 화면 높이의 68~72% |
| 맵 미리보기 | 본문 가로의 약 56~60% |
| 음식 목록 패널 | 본문 가로의 약 32~36% |
| 맵과 음식 패널 사이 | 본문 가로의 약 4~6% |
| 하단 다음 버튼 | 화면 가로 중앙 |

수치는 구현 시작점이다. 최종 검증에서는 레퍼런스 그림과 같은 정보 계층이 유지되는지를 우선한다.

## 7. 상단 스테이지 제목

### 7.1 표시 형식

```text
{stageId} : {stageName}
```

예시:

```text
3-3 : 저녁 마감
```

### 7.2 제한

- 스테이지 이름은 한글, 특수문자, 공백 포함 최대 30자다.
- 제목은 한 줄로만 표시한다.
- 제목이 두 줄로 넘어가면 글자를 계속 줄이지 말고 스테이지 이름 작성 규칙을 위반한 것으로 처리한다.
- 스테이지 ID와 이름의 기준선이 어긋나지 않아야 한다.

### 7.3 배치

- 제목 영역은 화면 상단을 가로로 길게 사용한다.
- 텍스트는 수직 중앙 정렬한다.
- 좌측 정렬 또는 중앙 정렬 중 하나를 사용하되 모든 스테이지에서 동일해야 한다.
- 레퍼런스 그림처럼 제목 주위에 충분한 여백을 둔다.

## 8. 맵 미리보기

### 8.1 목적

플레이어가 다음 스테이지의 설비 위치와 이동 동선을 미리 파악하도록 한다.

### 8.2 표시 내용

- 다음 스테이지의 전체 맵
- 벽과 이동 가능한 바닥
- 설비와 테이블 위치
- 제출대 위치
- 스테이지 시작 배치 데이터가 있을 경우 시작 슬라임 위치

### 8.3 표시하지 않는 내용

- 주문 카드
- 인게임 타이머
- 선택 원
- 작업 진행도
- 이동 경로
- 화재 진행 상태
- 실시간 슬라임 애니메이션
- 설정 버튼과 기타 인게임 HUD

### 8.4 생성 방식

다음 두 방식 중 프로젝트 구조에 맞는 방식을 선택한다.

1. 스테이지별 정적 미리보기 이미지 사용
2. 스테이지 데이터를 읽어 정지 상태의 맵만 렌더링

어느 방식을 사용하더라도 실제 게임 월드를 별도로 실행하지 않는다.

### 8.5 비율과 크롭

- 현재 16×10 맵의 비율을 유지한다.
- 가로나 세로를 강제로 늘려 타일이 찌그러지지 않게 한다.
- 미리보기 영역 안에서 전체 맵이 보여야 한다.
- 잘라내기보다 남는 공간에 여백을 두는 방식을 우선한다.
- 설비 아이콘이 축소 후에도 구분되는지 확인한다.

## 9. 음식 목록 패널

### 9.1 제목

패널 상단에 다음 문구를 표시한다.

```text
나올 수 있는 음식 목록
```

문구는 한 줄로 유지한다.

### 9.2 슬롯 구성

- 3열×2행 고정 배치를 사용한다.
- 최대 6개의 음식을 표시한다.
- 음식 순서는 스테이지 UI 데이터에 등록된 순서를 유지한다.
- 같은 음식을 중복 표시하지 않는다.
- 실제 음식 수가 6개보다 적으면 남은 슬롯은 비활성 상태로 둔다.
- 비활성 슬롯에는 임시 음식 아이콘이나 물음표를 넣지 않는다.
- 비활성 슬롯은 활성 슬롯보다 대비를 낮춰 클릭 가능한 항목처럼 보이지 않게 한다.

### 9.3 활성 음식 슬롯

각 활성 슬롯은 다음 요소로 구성한다.

- 원형 또는 둥근 배경
- 음식 아이콘
- 호버 외곽선
- 키보드 포커스 외곽선

음식 이름을 슬롯 아래에 항상 표시할 필요는 없다. 이름은 호버 정보에서 확인할 수 있다.

### 9.4 슬롯 상태

- 기본: 음식 아이콘을 정상 밝기로 표시
- 호버: 흰색 외곽선 또는 밝기 상승
- 포커스: 호버와 구분되는 포커스 표시
- 비활성: 아이콘 없음, 낮은 대비
- 정보 열림: 선택된 음식 슬롯을 계속 강조

## 10. 음식 호버 정보

### 10.1 동작

- 활성 음식 슬롯에 마우스를 올리면 음식 상세 정보를 표시한다.
- 마우스가 슬롯과 상세 정보 영역에서 모두 벗어나면 닫는다.
- 다른 음식 슬롯으로 이동하면 같은 상세 영역의 내용만 교체한다.
- 별도의 전체 화면 팝업을 열지 않는다.
- 맵 미리보기, TIP, 다음 버튼을 가리지 않는다.

### 10.2 배치

상세 정보는 음식 목록 패널 안에서 표시한다.

권장 방식은 다음 중 하나다.

1. 패널 하단 또는 중앙에 고정된 상세 영역을 두고 호버한 음식의 내용으로 교체
2. 슬롯 가까이에 작은 카드를 띄우되 음식 목록 패널 경계를 넘지 않게 배치

첫 번째 방식을 우선한다. 화면마다 팝업 위치가 달라지지 않고, 레퍼런스 그림의 우측 패널 구조를 유지하기 쉽다.

### 10.3 표시 항목

- 음식 이름
- 음식 아이콘
- 필요한 재료 아이콘과 수량
- 사용하는 제작 도구 아이콘
- 제작 단계가 여러 개면 왼쪽에서 오른쪽으로 이어지는 아이콘 순서
- 깨끗한 그릇이 필요하면 그릇 아이콘
- 제출이 필요하면 제출대 아이콘

### 10.4 현재 버섯 구이 표현 예시

```text
버섯 구이

[버섯 ×1] → [조리 도구] → [깨끗한 그릇] → [제출대]
```

- 불 슬라임만 조리할 수 있다는 규칙을 반드시 표시해야 한다면 조리 도구 아이콘 옆에 작은 불 속성 아이콘을 붙인다.
- 해당 아이콘은 제작 단계의 요구 조건만 나타낸다.

### 10.5 정보 출처

- 음식 이름과 아이콘은 음식 레지스트리에서 읽는다.
- 재료와 수량은 레시피 데이터에서 읽는다.
- 제작 도구는 실제 레시피 또는 상호작용 데이터에서 읽는다.
- 그릇과 제출 요구 여부는 실제 제출 규칙에서 읽는다.
- UI 전용 파일에 레시피 단계를 별도로 복제하지 않는다.

### 10.6 데이터 누락

- 음식 ID가 없으면 해당 슬롯을 활성화하지 않는다.
- 음식 아이콘이 없으면 임의의 다른 아이콘으로 대체하지 않는다.
- 레시피 데이터가 없으면 잘못된 순서를 추측해 표시하지 않는다.
- 누락된 데이터와 에셋을 개발 로그와 검증 결과에 남긴다.

## 11. TIP 영역

### 11.1 개수와 길이

- TIP은 최대 2개다.
- TIP 하나는 최대 2줄이다.
- TIP 문구는 한글과 공백 포함 최대 30자다.
- TIP 앞에는 `TIP:`을 표시한다.

### 11.2 내용

- 다음 스테이지에서 실제로 도움이 되는 짧은 문장만 사용한다.
- UI가 TIP 내용을 자동 생성하지 않는다.
- TIP은 스테이지 UI 데이터에 직접 등록한다.
- 등록되지 않은 TIP 자리에 임시 문구를 표시하지 않는다.

### 11.3 배치

- 레퍼런스 그림처럼 맵 미리보기 아래쪽에 배치한다.
- 두 TIP의 시작 위치와 줄 간격을 맞춘다.
- 다음 버튼과 겹치지 않게 한다.
- 문장이 길어져 다음 버튼 영역을 침범하면 데이터 제한 위반으로 처리한다.

## 12. 다음 버튼

### 12.1 배치와 스타일

- 화면 하단 중앙에 배치한다.
- 기존 시작하기와 설정 버튼의 외곽선, 흰색 패딩, 글자 스타일을 따른다.
- 목업의 빨간 사각형을 그대로 복제하지 않는다.
- 기본, 호버, 눌림, 비활성 상태를 구분한다.

### 12.2 동작

- 한 번 클릭하면 현재 스테이지 정보 화면을 닫는다.
- 다음 스테이지에 영입 단계가 있으면 기존 영입 화면 진입 지점으로 이동한다.
- 영입 단계가 없으면 실제 로딩이 필요할 때만 로딩으로 이동한다.
- 로딩이 필요하지 않으면 인게임을 시작한다.
- 버튼 연타로 상태 전환이 두 번 실행되지 않게 입력을 잠근다.

### 12.3 키보드

- Enter 또는 Space로 다음 버튼을 실행할 수 있다.
- 화면이 열려 있을 때 Q/W/E/R은 슬라임 선택으로 처리하지 않는다.
- ESC는 정보 화면 상태를 보존한 채 설정을 연다.

## 13. 데이터 구조

현재 코어 스테이지 정의는 다음 형태를 유지한다.

```ts
interface StageDefinition {
  id: string;
  name: string;
  orders: OrderDefinition[];
  timeLimitMs: number;
}
```

맵 미리보기, TIP, 음식 목록은 UI 전용 정보이므로 스테이지 ID를 키로 하는 별도 설정을 사용한다.

```ts
interface StageInfoUiConfig {
  mapPreviewKey: string;
  tipLines: string[];
  availableFoodIds: string[];
  nextStep: 'RECRUIT' | 'PLAY';
}

const stageInfoUiConfig: Record<string, StageInfoUiConfig> = {
  '1-1': {
    mapPreviewKey: 'stage-map:1-1',
    tipLines: [],
    availableFoodIds: ['mushroom-grill'],
    nextStep: 'PLAY',
  },
};
```

위 ID와 값은 구조 예시다. 실제 레지스트리와 에셋 키를 확인한 뒤 사용한다.

### 13.1 검증 규칙

- `tipLines.length <= 2`
- 각 TIP은 공백 포함 최대 30자
- `availableFoodIds.length <= 6`
- 같은 음식 ID 중복 금지
- 모든 음식 ID가 음식 레지스트리에 존재해야 함
- `mapPreviewKey`가 실제 미리보기 또는 맵 렌더 데이터에 연결되어야 함
- `nextStep`이 현재 게임 흐름과 일치해야 함

### 13.2 자동 추론 금지

- UI가 주문 배열을 분석해 음식 목록을 임의로 확장하지 않는다.
- UI가 새 음식 여부를 자동 판단하지 않는다.
- UI가 TIP을 생성하지 않는다.
- UI가 존재하지 않는 맵 미리보기를 임의 생성하지 않는다.

## 14. 화면 상태

필요한 상태는 한 화면 안의 호버와 포커스 정도로 제한한다.

```ts
interface StageInfoScreenState {
  stageId: string;
  hoveredFoodId: string | null;
  focusedFoodId: string | null;
  isTransitioning: boolean;
}
```

- `hoveredFoodId`: 마우스가 올라간 음식
- `focusedFoodId`: 키보드로 선택된 음식
- `isTransitioning`: 다음 버튼 중복 입력 방지

호버와 포커스가 동시에 존재하면 최근 입력 방식을 우선한다.

## 15. 시각 디자인

### 15.1 레퍼런스 적용

- 제공된 그림의 제목, 맵, 음식 목록, TIP, 버튼 순서를 유지한다.
- 좌측 맵과 우측 음식 목록이라는 큰 실루엣을 바꾸지 않는다.
- 전체 화면을 작은 카드 여러 개로 분할하지 않는다.
- 음식 상세 정보만 우측 음식 패널 안에서 바뀌게 한다.

### 15.2 게임 스타일 적용

- 굵은 외곽선
- 흰색 패딩
- 단순한 색면
- 축소해도 알아볼 수 있는 아이콘
- 기존 게임 버튼과 동일한 글자 처리

### 15.3 정보 우선순위

1. 스테이지 이름
2. 맵 미리보기
3. 나올 수 있는 음식
4. 음식 호버 정보
5. TIP
6. 다음 버튼

### 15.4 금지 사항

- 작은 카드가 화면 전체에 흩어진 대시보드 형태
- 맵 위에 음식 상세 팝업 표시
- 긴 설명문
- 빈 슬롯에 임의의 아이콘 삽입
- 화면에 점수나 랭킹 표시
- 목업의 임시 색과 자리표시자를 최종 디자인으로 취급

## 16. 컴포넌트 분리

최소한 다음 책임을 분리한다.

- `StageInfoScreen`
  - 전체 화면 조합
  - 다음 상태로 이동
- `StageTitleHeader`
  - 스테이지 ID와 이름
- `StageMapPreview`
  - 정적 맵 미리보기
- `AvailableFoodPanel`
  - 3×2 음식 슬롯
  - 호버 및 포커스 관리
- `FoodHoverInfo`
  - 음식 이름, 재료, 제작 도구, 그릇, 제출 흐름
- `StageTipList`
  - TIP 최대 2개
- `StageInfoNextButton`
  - 영입 또는 인게임 전환

실제 클래스명은 프로젝트 관례에 맞춰 바꿀 수 있다. 화면 전체를 하나의 거대한 컴포넌트에 넣지 않는다.

## 17. 구현 순서

### 단계 1. 현황 확인

- 정산에서 다음 스테이지로 넘어가는 실제 호출 지점을 찾는다.
- 첫 스테이지 시작 전 기존 슬라임 선택 흐름을 확인한다.
- 스테이지와 맵 레지스트리를 확인한다.
- 음식, 레시피, 설비, 아이콘의 실제 ID와 에셋 키를 확인한다.
- 기존 UI 스케일과 버튼 컴포넌트를 확인한다.

### 단계 2. 전환 상태 연결

- 정산과 다음 인게임 사이에 스테이지 정보 화면을 삽입한다.
- 첫 스테이지 진입 흐름에도 같은 화면을 연결한다.
- 정보 화면이 열려 있는 동안 게임 진행을 완전히 멈춘다.
- 다음 버튼의 중복 전환을 방지한다.

### 단계 3. 기준 레이아웃

- 상단 제목 영역을 구현한다.
- 좌측 맵 미리보기 영역을 구현한다.
- 우측 음식 목록 패널을 구현한다.
- 하단 TIP과 다음 버튼을 구현한다.
- 제공된 그림과 같은 정보 계층인지 캡처로 확인한다.

### 단계 4. 음식 호버 정보

- 3×2 음식 슬롯을 구현한다.
- 음식 호버와 키보드 포커스를 구현한다.
- 재료, 제작 도구, 그릇, 제출 정보를 실제 데이터에 연결한다.
- 음식 목록 패널 경계 안에서 상세 정보가 열리게 한다.

### 단계 5. 데이터 검증

- 제목, TIP, 음식 수 제한을 검사한다.
- 존재하지 않는 음식과 미리보기 키를 검사한다.
- 오류가 있을 때 임의 콘텐츠로 대체하지 않고 보고한다.

### 단계 6. 시각 검증

- 1280×720에서 전체 화면을 캡처한다.
- 음식 1개와 음식 6개 상태를 각각 확인한다.
- 각 음식 슬롯의 호버 상태를 확인한다.
- 긴 스테이지 이름과 TIP 경계값을 확인한다.
- 맵, 음식 패널, TIP, 다음 버튼 사이의 겹침을 검사한다.

## 18. 테스트 요구사항

### 18.1 단위 테스트

- TIP이 2개를 넘으면 검증 오류가 발생한다.
- 음식이 6개를 넘으면 검증 오류가 발생한다.
- 중복 음식 ID가 있으면 검증 오류가 발생한다.
- 존재하지 않는 음식 ID가 있으면 해당 슬롯을 활성화하지 않는다.
- 다음 버튼 입력이 한 번만 처리된다.
- `nextStep`에 맞는 다음 상태를 선택한다.

### 18.2 통합 테스트

- 스테이지 결과 뒤 다음 스테이지 정보 화면이 열린다.
- 첫 스테이지 시작 전 정보 화면이 열린다.
- 정보 화면이 열린 동안 타이머와 화재가 진행되지 않는다.
- 다음 버튼이 영입 또는 인게임으로 정확히 이동한다.
- 게임 오버 상태에서 다음 스테이지 정보 화면으로 잘못 이동하지 않는다.
- ESC 설정을 열었다 닫아도 정보 화면이 유지된다.
- 인게임 중에는 정보 화면을 열 수 없다.

### 18.3 음식 목록 테스트

- 음식 수가 1개면 1개 슬롯만 활성화된다.
- 음식 수가 6개면 3×2 슬롯이 모두 활성화된다.
- 음식에 호버하면 올바른 재료와 제작 도구가 표시된다.
- 다른 음식으로 호버를 옮기면 상세 내용이 교체된다.
- 호버가 끝나면 상세 정보가 닫히거나 기본 상태로 돌아간다.
- 비활성 슬롯에서는 호버 정보가 열리지 않는다.

### 18.4 시각 테스트

- 제목이 한 줄로 표시된다.
- 16×10 맵이 찌그러지지 않는다.
- 맵 전체가 미리보기 영역 안에 들어온다.
- 음식 목록 제목과 슬롯이 겹치지 않는다.
- 음식 상세 정보가 맵, TIP, 다음 버튼을 가리지 않는다.
- TIP 두 개가 정렬되고 다음 버튼과 겹치지 않는다.
- 버튼 글자와 아이콘이 축소되어 뭉개지지 않는다.
- 기준 그림과 같은 좌측 맵, 우측 음식 목록 구도가 유지된다.

### 18.5 범위 테스트

- 별도 도구 정보 카드가 없다.
- 점수와 랭킹이 없다.
- 약초, 물약, 스크롤이 없다.
- 주문별 1분 타이머가 없다.
- UI가 음식과 TIP을 자동 생성하지 않는다.

## 19. 완료 조건

다음 조건을 모두 만족하면 작업을 완료로 본다.

- 제공된 그림과 같은 화면 정보 계층을 유지한다.
- 상단에 스테이지 ID와 이름이 한 줄로 표시된다.
- 좌측에 다음 스테이지의 전체 맵 미리보기가 표시된다.
- 우측에 최대 6개의 음식이 3×2로 표시된다.
- 음식 호버 시 재료와 제작 도구를 확인할 수 있다.
- TIP 최대 2개가 맵 아래에 표시된다.
- 다음 버튼이 화면 하단 중앙에 표시된다.
- 화면이 열린 동안 게임 진행이 멈춘다.
- 다음 버튼이 영입 또는 인게임으로 한 번만 전환한다.
- 실제 데이터와 에셋을 사용하고 임의의 게임 규칙을 추가하지 않는다.
- 텍스트, 아이콘, 패널, 버튼에 잘림과 겹침이 없다.
