# 슬라임 공방 자원·제작 시스템 기획

## 1. 기획 목표

복잡한 레시피를 외우게 하지 않고, 주문을 보는 즉시 필요한 행동을 이해할 수 있도록 설계한다.

핵심 규칙은 다음과 같다.

> 약초의 색이 결과물의 색을 결정하고, 약초를 가져간 장소가 결과물의 형태를 결정한다.

```text
붉은 약초 -> 양조기 -> 붉은 물약
붉은 약초 -> 마법 테이블 -> 붉은 스크롤

파란 약초 -> 양조기 -> 파란 물약
파란 약초 -> 마법 테이블 -> 파란 스크롤
```

중간재와 다단계 제작 트리는 사용하지 않는다.

음성 명령은 `가져오기`와 `넣기`를 따로 지시하지 않는다. 플레이어는 물품과 목적지만 지정하고, 슬라임이 집기·이동·투입을 한 번에 수행한다.

---

## 2. 기본 자원

### 붉은 약초

- 붉은 소환진에서 주기적으로 생성된다.
- 소환진의 최대 재고에 도달하면 생성이 멈춘다.
- 주문에서 붉은 약초 자체를 요구할 수 있다.
- 양조기에 넣으면 붉은 물약이 된다.
- 마법 테이블에 가져가면 붉은 스크롤이 된다.

### 파란 약초

- 파란 소환진에서 주기적으로 생성된다.
- 소환진의 최대 재고에 도달하면 생성이 멈춘다.
- 주문에서 파란 약초 자체를 요구할 수 있다.
- 양조기에 넣으면 파란 물약이 된다.
- 마법 테이블에 가져가면 파란 스크롤이 된다.

---

## 3. 소환진

붉은 약초와 파란 약초는 각각의 소환진에서 자동 생성된다.

```text
현재 재고 < 최대치
-> 일정 시간마다 약초 1개 생성

현재 재고 = 최대치
-> 생성 중단
```

약초가 사용되어 공간이 생기면 다시 생성이 시작된다.

### 설계 의도

- 직접 채집하는 절차를 제거한다.
- 자원 수급보다 배분과 가공 선택에 집중한다.
- 소환진이 가득 차면 추가 생성 기회를 잃으므로 약초를 적절히 소비해야 한다.
- 약초를 원재료로 남길지, 미리 가공할지 판단하게 한다.

---

## 4. 기본 음성 명령 단위

### 핵심 원칙

음성 명령 하나는 행동 하나가 아니라 **물품 이동의 목적 하나**를 의미한다.

```text
[슬라임 이름] + [물품] + [목적지 또는 목적]
```

예시:

```text
"말랑아, 붉은 약초를 양조기에 넣어."
"말랑아, 파란 약초를 테이블로 가져가."
"말랑아, 붉은 물약을 제출해."
"말랑아, 파란 스크롤 하나 버려."
```

플레이어는 다음을 결정한다.

- 무엇을
- 어디로
- 몇 개

슬라임은 다음 행동을 자동으로 수행한다.

```text
물품 위치로 이동
-> 물품 집기
-> 목적지로 이동
-> 물품 투입 또는 내려놓기
```

### 사용하지 않는 명령 분리

아래처럼 집기와 투입을 따로 말하게 하지 않는다.

```text
"붉은 약초 가져와."
"그걸 양조기에 넣어."
```

이 방식은 중간에 새로운 판단이 없는데도 발화 횟수와 음성인식 지연만 늘린다.

### `가져와` 명령

`가져와`는 목적지가 불명확하므로 기본 명령으로 사용하지 않는다.

```text
"붉은 약초 가져와."
```

이 명령은 다음 중 무엇인지 알기 어렵다.

- 플레이어 앞에 놓기
- 손에 든 채 대기
- 제출대에 가져가기
- 특정 작업대에 넣기

따라서 실제 명령은 목적지를 포함한다.

```text
"붉은 약초를 양조기에 넣어."
"붉은 약초를 제출해."
```

---

## 5. 양조기

### 기능

- 약초 한 개를 넣으면 같은 색의 물약 한 개가 만들어진다.
- 완성된 물약은 양조기 내부 재고에 저장된다.
- 양조기에는 최대 재고량이 존재한다.
- 재고가 가득 차면 추가 생산을 할 수 없다.
- 재고에서 물약을 꺼내 주문에 제출할 수 있다.
- 필요 없는 물약은 꺼내 버릴 수 있다.

### 제작 시작

약초를 양조기에 넣는 순간 제작이 자동으로 시작된다.

```text
"말랑아, 붉은 약초를 양조기에 넣어."

붉은 약초 소환진으로 이동
-> 붉은 약초 집기
-> 양조기로 이동
-> 약초 투입
-> 붉은 물약 자동 생산
-> 양조기 재고 +1
```

별도의 `양조해`, `섞어` 명령은 요구하지 않는다.

### 재고 방식

색상별 개별 용량보다 전체 공용 용량을 우선 검토한다.

```text
양조기 최대 재고: 3개

현재 재고
- 붉은 물약 2개
- 파란 물약 1개
- 총 3/3
```

재고가 가득 차면 다른 색 물약을 만들기 위해 기존 물약을 제출하거나 버려야 한다.

---

## 6. 마법 테이블

### 기능

- 약초 한 개를 가져가면 같은 색의 스크롤 한 장이 작성된다.
- 종이와 잉크는 별도 자원으로 관리하지 않는다.
- 완성된 스크롤은 테이블 내부 재고에 저장된다.
- 테이블에도 최대 재고량이 존재한다.
- 재고가 가득 차면 추가 작성이 불가능하다.
- 스크롤을 꺼내 주문에 제출할 수 있다.
- 필요 없는 스크롤은 꺼내 버릴 수 있다.

### 제작 시작

약초를 테이블에 가져가는 순간 스크롤 작성이 자동으로 시작된다.

```text
"말랑아, 파란 약초를 테이블로 가져가."

파란 약초 소환진으로 이동
-> 파란 약초 집기
-> 마법 테이블로 이동
-> 약초 투입
-> 파란 스크롤 자동 작성
-> 테이블 재고 +1
```

별도의 `스크롤을 써`, `각인해` 명령은 요구하지 않는다.

---

## 7. 전체 물품 종류

초기 버전의 물품은 총 6종이다.

| 색상 | 원재료 | 양조기 결과 | 테이블 결과 |
|---|---|---|---|
| 붉은색 | 붉은 약초 | 붉은 물약 | 붉은 스크롤 |
| 파란색 | 파란 약초 | 파란 물약 | 파란 스크롤 |

플레이어가 학습해야 하는 규칙은 다음 두 개뿐이다.

```text
양조기에 가져가면 물약
테이블에 가져가면 스크롤
```

---

## 8. 주문 시스템

주문은 다음 물품을 요구할 수 있다.

- 붉은 약초
- 파란 약초
- 붉은 물약
- 파란 물약
- 붉은 스크롤
- 파란 스크롤

### 주문 예시

```text
붉은 약초 x2
파란 물약 x1
붉은 스크롤 x1
```

플레이어의 판단은 다음과 같다.

```text
붉은 약초 2개는 가공하지 않고 제출
파란 약초 1개는 양조기로 이동
붉은 약초 1개는 마법 테이블로 이동
```

음성 명령은 다음처럼 내려진다.

```text
"말랑아, 붉은 약초 두 개 제출해."
"말랑아, 파란 약초를 양조기에 넣어."
"말랑아, 붉은 약초를 테이블로 가져가."
```

### 주문 표기 원칙

효과명보다 색상과 형태를 중심으로 표시한다.

좋은 예:

```text
붉은 물약 x2
파란 스크롤 x1
```

초기에는 다음 명칭을 핵심 정보로 사용하지 않는다.

```text
회복 물약
공중부양 스크롤
순간이동 주문서
```

효과명은 필요하다면 작은 보조 설명으로만 붙인다.

---

## 9. 제출 명령

완성품을 꺼내는 것과 제출대로 운반하는 것도 하나의 명령으로 묶는다.

```text
"말랑아, 붉은 물약 하나 제출해."
```

내부 동작:

```text
양조기로 이동
-> 붉은 물약 꺼내기
-> 제출대로 이동
-> 제출
```

약초도 같은 방식으로 처리한다.

```text
"말랑아, 파란 약초 두 개 제출해."
```

내부 동작:

```text
파란 약초 소환진으로 이동
-> 약초 집기
-> 제출대로 이동
-> 제출
-> 필요한 수량만큼 반복
```

---

## 10. 폐기 명령

재고를 꺼내는 것과 버리는 것도 하나의 명령으로 묶는다.

```text
"말랑아, 붉은 물약 하나 버려."
"말랑아, 파란 스크롤 전부 버려."
```

내부 동작:

```text
재고 위치로 이동
-> 물품 꺼내기
-> 쓰레기통으로 이동
-> 폐기
```

### 폐기 원칙

- 버린 물품은 원재료로 되돌아오지 않는다.
- 별도 금전 패널티는 두지 않는다.
- 손실은 이미 소비한 약초와 작업 시간이다.

---

## 11. 명령 실행 전 검증

슬라임이 출발하기 전에 명령이 끝까지 실행 가능한지 검사한다.

### 주요 실패 상태

```text
SOURCE_EMPTY
필요한 물품이 없음

TARGET_FULL
목적지 재고가 가득 참

TARGET_BUSY
목적지를 현재 사용할 수 없음

UNKNOWN_ITEM
지원하지 않는 물품

UNKNOWN_TARGET
지원하지 않는 목적지

INVALID_STATE
현재 상태에서는 명령을 수행할 수 없음
```

### 처리 원칙

```text
양조기 재고가 가득 참
-> "붉은 약초를 양조기에 넣어" 명령 거부
-> 슬라임은 출발하지 않음
-> TARGET_FULL 표시
```

명령을 정상적으로 접수했다면 슬라임은 가능한 한 전체 작업을 끝까지 수행한다.

---

## 12. 재고의 역할

- 주문이 오기 전에 물약과 스크롤을 미리 생산할 수 있다.
- 어떤 색과 형태를 얼마나 비축할지 판단하게 한다.
- 최대치 때문에 모든 물품을 무한정 쌓을 수 없다.
- 잘못 예측한 생산은 이후 주문 대응을 방해할 수 있다.

예시:

```text
양조기 재고가 붉은 물약으로 가득 참
-> 파란 물약 주문 발생
-> "말랑아, 붉은 물약 하나 버려."
-> 공간 확보
-> "말랑아, 파란 약초를 양조기에 넣어."
```

---

## 13. 플레이어가 하게 되는 판단

- 약초를 그대로 제출할 것인가
- 물약으로 가공할 것인가
- 스크롤로 가공할 것인가
- 어떤 색의 재고를 먼저 쌓을 것인가
- 소환진이 가득 차기 전에 무엇을 소비할 것인가
- 양조기와 테이블의 빈 공간을 어떻게 유지할 것인가
- 잘못 만든 재고를 버릴 것인가
- 현재 주문과 다음 주문을 고려해 약초를 어디에 배분할 것인가
- 슬라임에게 어떤 목적 단위의 명령을 먼저 내릴 것인가

플레이어는 집기와 내려놓기를 세세하게 지시하지 않는다. 판단의 중심은 자원 배분과 목적지 선택이다.

## 15. 초기 권장 수치

아래 값은 테스트용 임시값이다.

```text
붉은 소환진 최대치: 4개
파란 소환진 최대치: 4개

양조기 최대 재고: 총 3개
마법 테이블 최대 재고: 총 3개

슬라임 동시 운반량: 1개
```

수량 명령을 받더라도 슬라임이 한 번에 하나만 들 수 있다면 같은 작업을 필요한 횟수만큼 반복한다.

실제 수치는 플레이테스트 이후 조정한다.

## 16. 초기 구현 범위

### 포함

- 붉은 약초 소환진
- 파란 약초 소환진
- 주기적 자동 생성
- 소환진 최대 재고
- 목적지 단위 음성 명령
- 집기·이동·투입의 자동 연결
- 약초 운반
- 양조기 물약 생산
- 마법 테이블 스크롤 생산
- 투입 후 자동 제작 시작
- 양조기와 테이블 재고
- 제출 명령
- 폐기 명령
- 명령 실행 전 상태 검증
- 약초, 물약, 스크롤 주문
- 색상과 형태 중심 UI
- 음성으로 개별 슬라임에게 작업 지시

### 제외 또는 보류

- 집기와 투입을 별도 음성 명령으로 분리
- 목적지가 없는 `가져와` 명령
- 별도의 `양조해`, `섞어`, `스크롤을 써` 명령
- 중간재
- 두 단계 이상의 제작 트리
- 효과명 기반 레시피 추론
- 종이와 빈 병의 별도 재고
- 잉크, 물, 연료 등 보조 자원
- 그룹 단위 명령
- 스쿼드 명령
- 자동 생산라인
- 복잡한 공장 시스템
- 제작물의 원재료 환원
- 책이나 상위 주문서 등 추가 제품군

---

## 17. 확장 원칙

새로운 제작 단계를 늘리지 않고 색상을 추가한다.

```text
노란 약초
-> 노란 물약
-> 노란 스크롤
```

색상 하나를 추가하면 새 규칙 없이 물품 세 종류가 추가된다.

- 노란 약초
- 노란 물약
- 노란 스크롤

초기 버전은 붉은색과 파란색만 사용한다.

---

## 18. 한 문장 요약

> 붉은 약초와 파란 약초가 소환진에서 주기적으로 생성되고, 플레이어는 `붉은 약초를 양조기에 넣어`처럼 물품과 목적지만 음성으로 지정하며, 슬라임이 집기·이동·투입을 한 번에 수행해 약초를 그대로 제출하거나 같은 색 물약과 스크롤로 가공하고 제한된 재고를 관리하는 시스템이다.
